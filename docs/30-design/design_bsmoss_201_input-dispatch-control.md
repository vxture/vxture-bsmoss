# 输入变化消费的退避、隔离与恢复

2026-11-02。I09 内部切片，承接 198/199 的事务捕获和授权消费；不代表常驻 worker 或生产上线。

## 追加记录与消费语义

新增 input_dispatch_event，按 workspace／change／subscription／revision 记录不可变的失败和恢复历史。运行身份只能 SELECT／INSERT，不能修改、删除；同租户变化外键、30位修订、限定状态／次数／错误代码和恢复依据唯一键由空库 DDL 约束。Prisma 只镜像标量，共36表，不提供旧库迁移。

处理成功仍只认 input_refresh_receipt。失败、延迟、隔离和重新开放均不生成消费回执，不把失败伪装成成功。任务及消费回执同一 SAVEPOINT；处理失败先回滚该工作，再追加失败记录，最后提交。失败账本本身写入失败时整个事务回滚。连接断开等无法继续使用事务的故障不能保证写下失败记录，仍保留为未消费，由监督进程恢复后再试。

## 有限重试与队首隔离

第1至4次失败分别延迟5、10、20、40秒，第5次 quarantined；可用时间由数据库时钟生成并判断，不使用调用端时间跳过退避。发现页排除未到期和隔离记录，每个完整授权范围／输出配置摘要单独记账；配置或范围改变不会覆盖旧分区记录。直接内部消费同样服从退避与隔离。单步执行跳过忙、未到期及隔离候选，处理下一条。

只存固定错误代码：序列化冲突、数据库不可用、容量限制、来源不可用、证据非法；不持久化异常原文、载荷、地址或凭据。身份、权限、范围及授权过期错误不记成来源失败。事务提交失败或当前权限失效不产生成功或失败回执。

## 规划错误也必须受控

消费前独立核验变化的来源／指标和稳定对象。测量变化用数据库 EXISTS 检查所有历史修订的站址／服务／设备范围，不将规划器1000条返回上限误当作授权边界。完成证明从账本中的稳定对象验权，不要求历史映射或能力可用才允许建立失败记录。

随后在工作 SAVEPOINT 内读取有界完整证据、推导影响、校验可信快照并入队。因此超长修订历史、缺少有效映射或能力等规划阶段错误也可以退避／隔离；范围外的历史对象仍直接拒绝，不借失败处理扩大授权。成功重放仍核验当前对象范围和清单摘要。

## 显式恢复

reopenInputChange 仅为内部服务，要求当前平台 data 面权益、metering.aggregate 产品权限及有限范围；不开放 HTTP、后台身份或来源审批权。只可重新开放最高记录为 quarantined 的分区，expectedRevision 防止覆盖并发处置，reasonRef 必填且唯一。追加 reopened／attempt=0，后续失败从1重新计数，历史记录不删改。

重复的同依据、同预期修订恢复请求返回相同修订；冲突依据重放、非隔离、已消费及过期／撤权均拒绝。恢复只允许重新尝试，不承诺来源问题已修复，也不生成来源完成签认。失败追加前重新核验主体、workspace、完整范围／配置摘要和有效期。
