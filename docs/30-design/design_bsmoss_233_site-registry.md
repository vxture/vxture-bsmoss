# 站址管理与分层档案设计

2026-11-03，P02 首版。产品入口为 launcher「站址资源」下的站址管理与服务关系；不添加全局业务侧栏。遵循用户“强业务视角，可以多层”“业务页面布满全屏”要求。

## 业务目标与层次

站址管理回答“有哪些站、谁在使用、承载什么、运行如何、用量如何、依据在哪里”。铁塔是建设和运营主体，物理站址是资源根对象；移动、电信、联通、广电及其他是服务对象。物理站址数与服务关系数分别统计，经营量不跨单位求和，站址总电耗不按运营商重复累加或自动分摊。

| 层次 | 页面或区域 | 核心动作 |
|---|---|---|
| 范围 | 左侧陕西／地市／区县资源树；窄屏下拉 | 缩小业务范围，保留其他筛选条件 |
| 台账 | /sites | 名称／编码／地址检索、站点类型／运营商／场景／共享方式／运行状态筛选、排序分页、行内关系展开 |
| 关系台账 | /sites?view=relations | 按站址与运营商稳定关系键查看承载资源、时段接通率与流量 |
| 单站总览 | /sites/[id] | 身份、主体、区县、塔房、三类摘要、关注事项与服务结构 |
| 单站分层 | 同一档案的六个业务页签 | 资源设备、服务关系、运行状态、经营用量及资料来源 |
| 空间／成果 | 地图与单站周期 HTML | 保留同站址、状态小时；经营周期独立为日周月 |

默认进入台账，无默认选中站址。单站为独立全宽页面，六层切换保持稳定站址 ID、列表筛选及分页返回上下文。地域树数字表示演示地域资源总数；主区摘要和分页数字按当前全部筛选计算。关系视图的运营商筛选只计算该运营商关系，物理站址仍按 ID 去重。档案始终展示该物理站全部服务关系，不把列表筛选误作单站权限或事实缺失。

## 档案内容

- 总览：铁塔资产编码、建设运营主体、业务场景、塔型／高度、机房、投运日期、经纬度、档案版本及关注事项。
- 资源设备：塔房资源、能源保障、无线承载；共用塔体、电源、电池、电表、环境设备与运营商无线设备分别标明归属和稳定编码。
- 服务关系：铁塔共用资源 → 运营商关系 → 通话／流量／短信；按服务对象显示状态、负载与接通率，并可进入地图时段用量。
- 运行状态：明确小时的负载、接通率、时延；物理站电耗、供电、温度及24小时走势，不混入经营累计。
- 经营用量：同一行展示地域与日期区间；固定位置日周月按钮；三类经营总量、趋势、运营商结构、明细与单站 HTML 报告下载。
- 资料来源：模型／指标版本、状态时间与经营周期；档案资料状态；权属、验收、真实变更历史未接入时如实显示，不编造附件或操作记录。

## 布局与设计系统

header 下使用100%宽高，台账地域树与表格分别滚动，分页固定在业务区底部；不套居中封顶内容宽度。窄屏地域改为级联下拉、摘要合为官方指标列表卡，台账自动切换官方ListCard，站名及档案入口直接可达；内容自然滚动，档案明细宽表在自身容器内横向滚动。首页、大屏、正式分析及正式报告同批移除内容最大宽度限制，管理域不变。

按首轮浏览器批注，台账取消重复的大标题和“演示数据”横幅，站址管理域名称与演示标识统一由公共header承载。地域、日期、状态小时与地图入口合为主区的一行紧凑工具栏；左侧地域树从header下直接起排。省／市／县均使用14px正文档，区县使用32px官方xl按钮，保留条目间距、缩进导线与选中高亮，不以小字和紧密行高压缩资源树。

资源概况按后续批注改为按需展开：桌面与手机均默认收起，工具行提供“资源概况”折叠按钮，和地图入口并列，不单占一行。展开时四项统计统一使用官方MetricListCard紧凑呈现，取消大幅装饰指标卡；支持键盘开合，保留物理站址、运营商服务关系、共享站址、运行关注四项统计口径。手机地图入口为带可访问名称的图标，以保留完整地域日期；台账筛选、当前结果数和分页始终直接可用。

列表头部进一步整理为两行：地域日期／时段与概况／地图为上下文行；台账／关系切换、紧凑检索、站点类型、筛选及重置为业务工具行。取消重复顶部结果数，数量统一在底部分页；删除建设主体常识性说明。地市区县和运营商／共享／场景／状态进入官方Popover组装的单选条件弹层，草稿内多项修改后一次应用，取消不生效、重新打开恢复已应用值；城市变更清空县，条件清空覆盖弹层六项，不影响外放站点类型和搜索。按钮显示生效条件数，地域旁只读显示数据所属日期与小时；手机工具行自然分行而非挤压。

全部新增基础控件和模式从已发布 @vxture/design-system 伞包导入，使用官方 ViewHeader、MetricGrid、PanelCard、DataTable、TableTitleCell、FilterBar、Pagination、Accordion、DetailList、Progress、Button 等。仅业务布局 CSS，间距／字体／颜色／侧栏宽度使用语义 token；不定义新控件或全局 token。

## 数据边界与实现路线

本批是可操作的陕西业务演示首版，显式 BSMOSS_PRODUCT_PREVIEW=on 才读取合成适配器，关闭后显示正式台账／档案尚未开放，不回退示例。复用现有1080站址 ID、地域和小时规则；资产、塔房规格与设备清单由独立确定性场景生成，明确演示资料属性，不冒充真实资产或巡检证据。

domains/site-registry/rules 负责严格筛选、稳定排序和安全业务链接；demo-store 独立读取合成资源、生成档案和聚合。页面只组装视图，经营周期复用现有单站周期服务及运营商日历规则，与 HTML 导出保持一致。

后续正式实现分为：真实站址主档与权属资料、服务关系有效期与版本、设备资源生命周期、经授权的档案维护／导入／审阅及变更审计。不能将演示写入正式证据库；本批不开放虚假新建、导入、编辑、删除或审批按钮。无 DDL、旧库迁移、费用计算或退役影响开发。

## 验收

实际验证筛选交集、两类对象计数、稳定分页／排序、空结果、非法范围、返回上下文；三个经营周期与运营商明细、现有单站报告总量一致。桌面／中宽／手机检查全宽、独立滚动、层级切换、地图双向下钻、周期和下载。正式来源授权、平台权限与环境、业务验收不因演示完成而关闭。

## 搜索、站点类型与刷新语义（2026-11-03）

检索使用官方 InputGroup／InputGroupAddon／InputGroupInput，放大镜查询按钮置于框内，同时支持回车提交。桌面宽度采用公开 container-overlay-md token（标准密度224px），不随可用空间无限拉长；手机占满工具行。

首个外放下拉为站点类型：全部、地面站、楼面站。该维度描述物理承载形态，与城区商圈等业务场景、运营商服务关系分别建模。当前演示分类与已有楼面抱杆／地面塔体记录一致，不生成没有对应档案的室分或微站。类型参与站址与关系视图共同的筛选交集、概况计数和分页；下钻与返回保留类型，总览显示类型。运营商进入筛选弹层，多条件一次应用。

台账不再提供历史小时下拉。区域旁只读显示源数据时点；右侧提供刷新按钮和页面读取时间（北京时间）。刷新以 router.refresh 重新请求服务器读模型，服务器完成读取后生成 readAt，保留筛选、分页、展开、概况开合和搜索草稿；等待返回时禁用刷新，不能用客户端点击时钟冒充读取成功。演示刷新不触发上游采集，固定源时点不会随刷新改成今天。真实接入后仍需独立来源水位与同步任务状态，不能把页面读取时间当采集完成时间。显式旧URL的hour兼容保留，地图与档案继续支持历史小时分析。

## 字号与字重收敛（2026-11-03）

站址台账和档案统一按角色排版，标准字号偏好下只使用四档：12px辅助信息（编码、日期、刷新时间、说明、状态徽章），14px业务正文与操作（地域树、表格主数据／表头、按钮、输入、选择、分页），16px标题（系统名、域名称、档案标题、区域标题），20px品牌与已有关键读数。档案18px标题合并到16px，常规表格数值／地域由12px提升到14px，名称按钮由600收敛到500；辅助信息保持常规字重，标题保持600。表格行号仍属于辅助索引，不与业务读数混淆。

使用官方语义字号／行高／字重token，通过站址域局部样式覆盖官方组件的排版；筛选浮层有单独局部作用域，避免portal挂载丢失规则。不给全局token赋值，不修改设计系统包，不用硬编码px；用户Small／Large字号偏好继续由官方token联动。统一字号后保留已有控件高度和业务结构，实际检查手机日期、工具行换行、表内横滚、筛选浮层与档案多层内容。

## 展开服务关系弹性布局（2026-11-03）

台账行内展开默认四家运营商同一行展示，取消固定sm两列／xl三列。业务容器使用flex-wrap，各项以公开overlay-sm宽度token作为可读基准，等分剩余空间；不足时自然换行，不能为保留列数压缩文字。卡片内部由左右并列改为纵向：运营商、通话／流量／短信、服务档案入口，减少单项最小横向需求；字号沿用14／12体系，内距采用sm、展开区md。实际数量由服务关系决定，五家亦自适应，无固定占位或运营商丢失。

展开区以列表可视容器为宽度基准（inline-size容器＋cqw），不继承横向溢出的表格总宽，避免第四卡排在当前视窗以外。表格仍可独立横滚，展开卡片按实际可见宽度决定换行。

## 透明操作列与统一操作面板（2026-11-03）

站址台账、关系列表与单站服务明细统一使用发布版ActionMenu（三竖点触发＋官方菜单面板），替换行尾单一箭头。站址／关系菜单只提供已有档案、运行状态和经营用量入口，服务明细保留原时段用量地图入口；手机ListCard使用同一官方actions槽。无编辑、删除、审批等未交付动作。

操作表头与单元格采用透明背景，显露所在行背景。取消该透明列的sticky叠层，跟随表格横滚，避免业务内容从透明操作列下穿透重叠；原表格排序、展开、行hover及独立横滚不变。业务域局部样式覆盖，不修改全局token或设计系统包。

行hover统一在tr上绘制，同行单元格透明，避免原组件逐格hover使透明操作格与其他格底色不同。该规则限定当前无勾选态的站址操作表，展开跨列内容不受影响。

## 地域面板与透明工作区（2026-11-03）

参照单站档案页的白色header与淡蓝灰工作区，台账沿用ShellViewport和官方workbench底色；深色模式使用原有主题表面阶梯，不定义新颜色或全局token。此处借鉴背景配色，不新增地图或在线瓦片请求。

地域树以普通flex布局置于工作区，四周lg留白、与内容区lg间距；圆角、语义描边和官方68%卡片veil形成独立面板视觉，无fixed／absolute定位。树内部滚动和区县14px／32px可读尺寸保留。主区移除白色容器及外框，表格透明直接显示工作区底色，保留官方表头实线与行间虚线。

内容顶部使用官方Breadcrumb展示省／市／县，可返回上级范围并保留类型、排序等查询上下文。桌面面包屑前提供地域面板收放按钮及aria-expanded／controls；收起释放侧栏宽度，主区保留左右lg留白并自动铺满。收放状态独立于查询内容，在筛选、排序和刷新时保持；新开页面默认展开，不新增持久偏好。窄屏继续由筛选弹层选择地域，不显示无对应侧栏的收放按钮；手机上下文自然两行，完整保留源时点。中宽屏将刷新文字与地图文字收为图标，避免县级面包屑与时间相互覆盖。

行内关系展开区内距改为sm，在新四周留白布局下仍优先四卡同行；更窄时自然换行，不压缩单卡最小可读宽度。

按同轮补充批注，运营商名称本身作为服务档案入口，删除每卡重复的“服务档案”动作行。卡片下方使用官方Progress显示该运营商的小时负载率及百分比，明确18:00等状态时点；负载率为该运营商used／capacity，不是服务份额，不以四家百分比加和为100%。指标与单站服务档案同源，运营商筛选不隐去所展开物理站址的其他关系。

台账主列表的时段负载沿用同款官方Progress，上方右对齐的百分比使用body-small／muted-foreground（标准12px），降低数字视觉权重。手机站址卡片使用相同组合，保留“时段负载”标签；排序与原物理站址used／capacity口径不变。

地域面板标题改为“地图图标＋陕西·资源＋全省资源总数”，总数右对齐且淡化；移除树中重复的省级按钮和默认选中背景，树直接从地市开始。返回全省沿用内容面包屑的陕西省上级链接或筛选地域条件。面板收放使用官方ShellIconButton的sidebar图标，与配置域统一导航图标一致，非active、常态透明，仅保留官方hover／focus反馈。

地域树、台账纵向滚动区及表格内部横向滚动区隐藏原生滚动条，不再预留滚动条槽，保留overflow滚动与滚轮／触控板操作。两块主滚动区域可键盘聚焦，提供可访问名称和官方ring语义色焦点轮廓，方向键／PageDown等仍可滚动；仅站址台账局部生效，不改变档案或其他页面滚动条。
