# 周期报告发布与撤回

本批接续设计209。generated持久快照继续不可变；发布是产品报告的可见版本选择，不是来源签认、费用审批或外部部署。

## 命令与状态

内部服务只接受reportId、明确reportRevision及manifestSha256、expectedEventRevision、commandId、action和reasonRef。所有版本使用30位整数字符串。发布需要当前生成版本、当前可信输入、完整数据及全部必要范围；未接入、缺数、过期或未发布依赖不能发布。完整性与当前新鲜度分别核验，全部检查和发布账本在同一RR事务内。

撤回不要求旧报告仍然新鲜或仍为最新生成版本，但必须指向当前活跃发布的原修订及摘要，保留完整历史授权检查。只追加事件，不改报告或删除历史。生成新版本不自动发布或撤回旧版本；旧发布仍可追溯，回看单独显示新鲜度。返回的current仅指同一数据库快照，不承诺提交之后输入不会变化。

每个报告串行追加eventRevision，预期版本CAS；commandId在租户及报告内幂等，同命令不同载荷或主体拒绝。成功重放仍核验当前身份、显式权限及原报告完整scope，但不重新要求原发布仍新鲜，不会复活已撤回发布或回退head。重复的新命令发布同一活跃修订拒绝；撤回后允许同一生成修订重新发布，但须重新通过当前检查。

## 存储与授权

空库baseline新增report_publication_event及report_publication_outbox。事件绑定同租户报告修订及摘要、前序事件、命令、动作、依据、操作者和数据库时间。数据库触发器保证连续链、撤回目标及追加不可变；outbox精确引用该事件。事件与outbox及提交前再验权原子，失败全部回滚。

reports.publish为显式本地权限，不自动赋予owner；读仍用metering.view。生产组合根沿实际RP、平台权益及本地有限grant；不使用演示授权或样例。公开本批只提供GET发布历史选择与当前事件关系，命令仍内部调用。旧事件返回isActive=false，不把历史发布误呈现为当前活跃发布。

## 验证与边界

实际PostgreSQL验证发布／撤回／重发、CAS／幂等／并发、完整与新鲜度门槛、旧生成版本／输入变更、完整scope／租户、撤权及outbox故障全回滚、SQL链／不可变权限和读后再验权。异步HTML导出、下载再次验权、公开命令、正式页面及调度留待下一切片；本批不是正式上线或完整I12交付。

## 发布替换范围补充（2026-11-03）

替换一个活跃发布，同时使原发布失去活跃地位。操作者必须拥有新报告与被替换原快照的完整scope并集，不能仅凭新报告较窄范围和猜到的CAS版本间接撤下较宽发布。事务在追加前读取原快照并校验其摘要／范围，写后再次验证该并集；旧数据已经stale也不能跳过范围。

幂等重放仍核验原命令的全部作用范围：沿该事件的previousEventRevision恢复当时的前序事件；若原命令替换的是published，原被替换快照仍参与并集。不能改用今天的发布head，也不能因为目标已经被替换就缩窄原命令授权。撤回后另发的新命令，只按该次实际影响的范围核验；历史较宽范围不会永久附加到所有后续操作。后来扩大当前发布范围，不应阻断原本只作用于较窄范围的旧命令查询式重放；重放仍不改变head。
