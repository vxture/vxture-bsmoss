# 系统与接入设计

> 范围更新 V0.2：本阶段仅周期性用量分析；本文涉及合同、费率、对账、审批和冻结账单的内容
> 均为未来扩展，不属于当前实施范围。粒度、报告和指标口径以
> [周期分析规格](../20-specs/60-periodic-usage-analysis.md) 为准。


## 逻辑组件

来源系统 → 连接器 → 原始证据存储 → 标准化与质量处理 → 领域存储 → 聚合任务 →
查询服务 → 监管门户 / 运营商门户 / 分析服务。

门户使用 Next.js 组织，与 yucer 一致；领域服务不依赖页面生命周期。
首期采用模块化单体加独立 worker，避免把每个领域提前拆成微服务。
关系数据建议 PostgreSQL；原载荷按容量评估对象存储；Redis 仅做缓存或协调，不能替代账单与证据权威存储。
消息队列是否单独引入由接入速率与失败恢复需求决定，未选型前不承诺特定组件。

## 接口边界

连接器负责协议、认证、来源分页和源字段解析；领域服务负责业务身份、规则与权限。
接入身份只能提交授权 source 的数据，不能自选 workspace 或运营商范围。
外部回调验签、时效、防重放；文件接入记录文件摘要、行号、版本和解析错误。

建议应用接口资源：stations、station-services、sources、ingestion-batches、usage、
metrics、alerts、contracts、statements、reconciliations、analysis-jobs。
具体路径及错误 envelope 在继承平台契约后确定，此处不另造契约。

列表采用游标分页、上限和时间窗约束；聚合查询声明粒度与数据水位。批量导出异步执行，
执行及下载再次检查权限；权限变更后不允许继续下载先前已失权的结果。
长任务统一记录状态、进度、输入摘要、重试次数和失败原因。

## 一致性与任务执行

业务提交与待发事件采用同事务 outbox。worker 至少一次处理，消费侧以业务键幂等。
数据库唯一约束负责并发去重，不能仅依赖“先查再写”或缓存锁。
冲突重放进入隔离队列并留证。重试采用退避与上限，失败进入待处理清单。

聚合按水位推进；迟到数据生成新聚合版本。结算快照引用确定版本，重跑不能重复收费。
批准、冻结与调整使用事务和版本条件更新，避免并发审批或过期页面覆盖。

## 平台与权限

复用 C1 登录身份、C2 能力开通、C3 开通及产品商业用量契约。
业务 feature/permission 目录与档位到功能的能力矩阵由本产品管理，不复用 yucer 能力键。
平台登记商业产品及计划，不配置本产品的功能键；平台商业权益与产品本地权限分开解析。
能力门 → 操作权限 → 数据范围 → 规则校验 → 持久化。查询、导出、异步任务和模型工具一致执行。

审计覆盖敏感查询、导出、映射修改、合同变更、质量核验、审批和模型建议采纳。
来源密钥由密钥管理注入，日志不输出密钥或原始敏感载荷。不采集个人用户通信内容。

## 可观测与故障恢复

指标：来源延迟、吞吐、失败率、隔离率、重复率、队列积压、聚合水位、查询耗时、
权限拒绝与账单差异。按 source/workspace 聚合，避免以每站址作为所有指标标签造成高基数。

连接器故障可单来源暂停；断点恢复按来源游标和幂等键回放。数据库备份与原始证据保留期
需要业务确认；上线前完成恢复演练，并据实测确定 RPO/RTO。
