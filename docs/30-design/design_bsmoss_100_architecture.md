# 架构与 yucer 的对应关系

沿用 portals/app、portals/packages/shared、deploy/database/ddl、scripts/guardrails 和
编号 docs 的布局。领域内部采用 lib/rules.ts（纯规则）、service.ts（权限与编排）、
store.ts（持久化端口）；数据库适配器后续放 prisma-store.ts，禁止规则直接访问数据库。

本次复用 yucer 的组织逻辑与文档编号检查器，不复制销售领域、历史交付状态或私有平台依赖。
当前应用包是无 HTTP 入口的领域内核；后续增加 Next.js 门户，并接入 C1/C2/C3 平台契约。

规模方案：按站址、运营商、类型、时间粒度组织索引；原始采集与聚合查询分离，按来源限流、
批量写入、背压、失败隔离、断点续传。查询必须分页和限定时间窗，禁止一次加载全省明细。
约 11 万站址不能推导采样吞吐量；需确认指标数、采样频率、单条大小、保留期和并发量后再分区与压测。

首批 DDL 只落站址与计量内核；不是全量数据模型。其余领域只定义写入边界，避免虚构接口。
