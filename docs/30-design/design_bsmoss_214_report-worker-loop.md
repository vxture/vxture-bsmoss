# 报告生成与导出执行循环

接续213。把登记报告生成与持久导出组成可持续执行的内部worker核心。平台机器身份provider、进程托管和真实部署仍是单独出口；本批不在Next启动时安装定时器、不复用用户cookie作为长期机器身份、不伪造后台账号或自动grant。

## 有限工作集

`createReportWorker`由可信组合根传入Pool、AccessPorts与静态配置：固定workspaceId／subject、最多64个登记scheduleIds、是否处理导出、每轮最多1–25个步骤和1–60秒轮询间隔。配置不接受scope、token或任意回调地址。身份包装器在每次解析时要求真实身份与固定租户／主体一致；选择器本身不赋权。

每个登记形成独立工作通道，执行扫描→取一个当前修订pending→生成；导出形成一个通道，取一个已授权pending→执行。工作通道轮转，每轮最多访问全部通道一次，最多执行配置的步骤数；一个暂停或出错登记不会占住其他通道。没有自动发布动作，所有生成／执行继续沿既有单RR事务、有限scope和末次验权。

报告数据日历使用可信服务业务时钟，进程退避使用performance.now单调时钟，不因服务器校时提前反复重试。每通道抛错独立退避5／10／20／40／60秒并封顶；成功调用重置连续失败次数。数据库内作业的5次重试／dead保持原义，进程级退避不重置任务次数，也不会自动恢复dead。

## 导出待办发现

`ReportExportStore.pending`与授权门面新增明确limit1–25，只需独立reports.export.execute，普通reports.export不能枚举后台待办。SQL先对精确历史报告的完整requiredScope过滤租户、来源、站址、服务、设备、全部指标及物理站参数开关，再按available_at与ID的C顺序取limit。只返回due pending标识，不返回正文、全库数量或未授权任务信息。

逐一核验被选作业及其不可变报告／SHA，返回前再次核对全部必要scope并集、身份、权益、权限和有效期。读取故障或损坏证据必须报错，不作为空列表。待办发现不是任务认领，执行仍以SKIP LOCKED裁决；发现后撤权也必须再次失败。

撤回／过期报告的pending导出不在发现阶段隐藏，否则会永久留队；执行器按既有规则保存dead及固定原因。成功任务、dead和未来available_at不进入待办。已发布内容不重新绑定到新事件，下载仍独立再次验权。

## 生命周期与观察

`createWorkerLoop`只构造控制器，显式`run(signal,onCycle)`才开始循环。禁止同一实例重复run；run期间手工tick返回busy，手工tick本身也不会重入。各通道串行，无fire-and-forget数据库任务。停止信号立即结束空闲等待，阻止新通道及下一事务的派发；在途事务继续完成或自行回滚，run直到其实际结束才返回。扫描已提交的pending不会因停机丢失，下一实例从数据库恢复。

宿主必须监听真实SIGTERM／SIGINT，触发AbortController，await run结束后才能关闭自有Pool。数据库连接与语句超时、进程宽限期由部署环境显式配置；本核心不强杀连接、不冒充已回滚。宿主观察器抛错时run明确失败，防止监控坏了却静默声称持续运行。

每轮返回通道索引、固定状态／分类、连续失败次数及退避时间，不返回异常正文、SQL、token或原数据。snapshot只含进程内调用统计和各通道最后状态；重启会清零，不能当作持久任务审计、生产就绪或容量证明。持久事实以作业／attempt／报告／制品为准。新建实例不会清空数据库退避、尝试次数或成功回执。

## 验收与边界

单测覆盖有限公平轮转、独立退避及封顶、观察输出不泄密、重入、停机空闲计时器／在途等待、观察器失败、单调时钟倒退。实际PG验证授权先于分页、五维scope与独立物理站开关、末次撤权、租户及固定机器绑定、撤回任务终态、事务中断与新实例恢复、暂停登记隔离、生成和导出联动、扫描后停机与导出提交中停机。

本批不改DDL／Prisma，仍55表空库，无旧库迁移。尚无真实机器provider、生产后台进程、聚合／变化消费通道宿主、全省配置枚举与分片、dead受审恢复、历史报告变化传播或运行监控外发。I09／I12保持in_progress；Beta、11万站与3倍突发、安全恢复、业务UAT和生产批准仍需真实环境证据。
