# 业务流程设计

> 范围更新 V0.2：本阶段仅周期性用量分析；本文涉及合同、费率、对账、审批和冻结账单的内容
> 均为未来扩展，不属于当前实施范围。粒度、报告和指标口径以
> [周期分析规格](../20-specs/60-periodic-usage-analysis.md) 为准。


## 采集与质量状态

接入批次：created → running → succeeded / partial / failed。
partial 必须同时呈现成功量、隔离量、错误类型与重跑范围，不能覆盖为全部成功。
重复请求使用稳定幂等键；来源修订同一事件需要新的修订标识和前序引用，原载荷不可覆盖。

标准化处理：原始证据 → 来源解析 → 标识映射 → 单位规范化 → 累计转增量 →
质量检查 → verified / pending / rejected → 聚合。

映射缺失进入 pending；非法单位或载荷进入 rejected；计数器复位、回绕和异常负增量进入
待核验，不生成负用量。质量结论单独版本化，保留审核人、原因、输入证据与规则版本。

采集时刻、来源发生时刻与业务时间窗分别存储。迟到事件重算开放窗口；冻结账期内的迟到数据
进入调整流程，不静默修改已确认账单。

## 运行告警

告警状态：open → acknowledged → investigating → resolved → closed。
误报以 closed 加关闭原因标明；再次触发生成新事件并关联前次告警。
原始告警证据不可更改；状态变化追加事件，记录操作者、时间和理由。
同站址、同指标、同规则版本的持续异常按去重窗口合并，避免重复派单。

未收到数据只说明不可判断；只有明确规则及心跳证据才能认定离线。
站址是否在线与数据接入是否新鲜分别展示。先实现规则阈值，后续再引入模型辅助解释。

## 费用结算

账单状态：draft → calculated → reconciled → submitted → approved → frozen。
submitted 可驳回到 draft；驳回后修改产生新版本。approved 后只允许冻结或有审计记录的撤回，
frozen 后更正必须建立 adjustment，不原位重写。结算确认不等于实际资金支付。

calculated 固定合同、费率、归属映射、输入快照、规则与舍入版本；存在费率缺口、区间重叠、
未归属或未核验数据时阻止进入 reconciled。缺失数据不得作为零用量自动结账。

reconciled 记录运营商对账文件摘要、匹配结果、差异原因、处理依据；submitted 后锁定版本。
approved 必须由另一位有权成员完成。建议以提交时质量快照和全部差异处置记录为前置条件，
差异容忍阈值由合同或结算制度确定，禁止硬编码为“自动通过”。

## 智能分析

查询 → 范围校验 → 读取已授权聚合与证据 → 确定性计算 → 模型解释 → 返回引用和限制。
模型不得自行扩大时间窗、跨主体查询或批准账单。建议接受后仍通过同一业务服务权限门。
