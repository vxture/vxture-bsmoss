# 登记分区与周期种子

2026-11-03。I09下一切片：将周期扫描的有限scope、输出策略和稳定种子从调用者临时参数提升为持久审阅配置。仍只提供内部授权服务，不登记虚假机器账号或启动生产调度。

## 配置与生效

refresh_partition_revision追加配置，按workspace／id严格递增修订，包含实际principal_subject、active／paused、有限scope、输出／粒度策略、显式种子、审阅依据与数据库actor。refresh_partition_head由固定触发器同事务维护；运行账号只读，不能自行扩大分区或恢复暂停配置。配置SHA为PostgreSQL JSONB原始envelope摘要，读取时独立核验；规范化语义摘要另存，二者不混用。

内部enqueueRegisteredPeriodic只接收分区id，身份来自已有可信AccessPorts。当前平台data权益／aggregate权限必须有效，主体精确匹配登记subject；配置的所有来源、站址、服务、设备、指标及站级参数范围都必须是当前grant子集。实际使用的依赖指标也必须在有限scope内；直接比率不强加未使用的次数依赖。种子的mapping归属和有效期由既有可信快照核验，登记配置不是授权或来源完成证明。

## 可靠扫描

同一RR事务锁定head共享锁，读取精确配置，使用服务器时间规划闭合日／周／月；最多12个种子、64个目标，超限全批失败。没有测量的有效种子也会产生missing结果候选，不用已有事实倒推站群。每个种子notBefore为明确起点，沿72小时回看，长历史回补仍另走有界修订／显式任务。

持久refresh_scan_receipt绑定配置修订、扫描小时、原始配置SHA、规范语义摘要和完整任务清单。任务与回执同事务；同配置同小时重放返回同回执，不重复排队。回执前再次核验当前完整登记scope和身份，撤权或过期全回滚。head共享锁使并发新修订在旧扫描结束后才生效；RR快照在取锁前遇已变化head则安全回滚。

修订或暂停配置不删除既有任务、结果及扫描证据；已排队执行仍按当前真实grant核验，不能声称暂停等于撤权或取消。变化消费现有scope／policy摘要与登记分区的接线需后续在同一事务中完成，不能仅套用两个独立事务称为登记消费。

## 验收与边界

空库新增两张配置表、一张扫描回执表，共41表；Prisma标量同步，无旧库迁移。实际PG验证运行权限、修订链、租户引用、暂停／主体／scope拒绝、无事实种子、同小时重放、新小时、新配置、回执故障回滚、撤权和并发配置生效边界。

分区采用显式小批种子，尚无全省站群自动登记、分区分配器、机器身份provider或常驻进程。生产配置必须来自真实平台登记及审阅；本地夹具不创建生产配置。11万站容量、真实来源对账、Beta、安全恢复、UAT与生产批准另行验收。
