# P1跨页面任务消息

2026-11-06，接续设计243/245。先补齐已有已接收增量任务的跨页面查询入口；上游接收生命周期监管仍需单独完成，不把既有重算任务冒充来源拉取任务。

## 服务端

复用receivedDataUpdates的job_view交互身份、完整有限scope与微秒keyset分页。list与notifications共用同一筛选查询：工作区和全部对象范围先过滤再LIMIT。消息每页UI取5条、服务上限10条，按任务提交时间排序，支持翻页，不使用隐藏总数。

在一个REPEATABLE READ事务内重建该页任务实际派发/重算状态与当前注册修订，返回前再次校验整个响应所需scope的并集、原主体、工作区和原始有效期。途中失权则整页拒绝，不返回部分结果。摘要只含任务身份、提交时间、阶段、计数及配置变化；不包含原量、manifest、执行错误原文或失败对象清单。恢复链沿原工作台规则追踪，processed始终publishesAvailability=false。

GET /api/data-updates/notifications要求已启用OIDC及RP会话，沿原strict limit/after验证与private no-store响应。它是实时重读的任务状态投影，不是持久事件/未读收件箱，不声明已读时间、完成时间或推送投递。

## 页面

沿已认可Header四工具组32px外框、16px图案，复用官方Drawer、Button、StatusBadge、EmptyState及DS tokens。消息按钮打开抽屉后读取当前授权任务，展示任务组、提交时间、实际阶段和增量/重算计数。失败与配置变化有明确说明，名称直接定位原任务详情；全部任务入口进入原工作台。此处只读，复核与恢复仍在原权限控制页面执行。

抽屉打开且文档可见时每10秒读取，15秒请求超时。关闭卸载、隐藏和离页取消读取，隐藏清空记录；返回可见重新读取。出错/失权清空旧记录及阶段通知，停止自动重试，可人工重新查询。切换页面、重开抽屉不依赖浏览器缓存，从持久任务重建状态；不使用localStorage/IndexedDB保存授权记录。状态变化仅在打开的抽屉内通知，不制造全局未读数量或假推送。

未登录/未接入身份显示准确门槛，不查询正式任务API，不填充合成消息。接收成功、已处理和共同可用版本发布保持不同含义，不推进业务页数据更新时间，不修改旧报告。

## 边界

没有来源接收任务的新队列/生命周期/失败账本、业务按需接收入口、真实来源适配器、机器ingest授权或共同可用版本发布。无DDL/Prisma/依赖/自动赋权变化。真实来源授权与字段原件、稳定快照/变化流、平台及环境、业务验收与生产批准依赖保持。
