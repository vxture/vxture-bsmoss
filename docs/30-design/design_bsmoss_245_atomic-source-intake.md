# P1持久来源接收与输入位置

2026-11-06，接续设计244。只读拉取准备之后，提供内部持久接收协调器；不在本批开启真实连接器、机器ingest、前端正式同步按钮或数据可用版本发布。

## 注册与范围

source_binding_revision由受审管理路径追加，包含标准binding、来源外键、active/paused、规范化指纹、数据库独立摘要和审阅引用。严格连续修订以触发器原子推进source_binding_head，运行角色不可注册、改写或删除。注册结构校验不是来源授权文件签认，真实使用还需要D05材料和环境。

sourceIntake.receive只接受bindingId与取消信号，scope、workspace、actor和来源游标均由可信身份及数据库读取。首次授权为既有data plane ingest；完整所需来源/站址/服务/设备/指标范围、原始主体与有效期在接触适配器前、准备后、提交过程中及最终边界重验。保留当前服务身份不具ingest的限制，不自动分配权限。

配置变更发生于网络拉取期间时拒绝旧准备。提交期持有配置head的共享行锁，受审新修订等待事务结束，不能在事务中悄悄换来源/转换或scope。已有位置绑定原配置指纹，新配置不能直接继承旧游标；后续需要明确受审的重基准流程，本批不自动重置。

## 持久接收

来源head/分页准备在数据库写事务外完成，使用244的固定快照与资源限制。随后READ COMMITTED事务取得同租户/binding的非等待互斥锁，锁定并复核注册，再读最新回执。prepared只能由当前内部调用链产生，浏览器没有提交prepared或可信游标的接口。

复用PgMeasurementStore的原量写入实现，将事务所有权提升给协调器，保留映射有效期/真实服务与设备/站级参数/指标/原始证据重放校验。独立append仍自行BEGIN/COMMIT；内部appendInTransaction不另开事务。所有记录质量pending，不用来源声明自动批准；同事件修订按数字递增写，来源乱序不造成虚假的前驱缺失，真正缺前驱由原FK拒绝。

重叠扫描重放保留原始pending入库决定的主体。此例外仅适用于connector-intake-v1及source_quality_review_required完全相同的pending初始决定，原量、摘要、规则及原因仍逐字段核对，既有独立append严格重放语义保持。后续质量修订继续追加，不改原决定。

同事务追加source_intake_receipt，保存plan、前回执、输入/输出位置、每条measurement引用及摘要、原量清单摘要、实际插入/重放数、未验证来源声明和接收主体/时间。source_intake_receipt只可INSERT/SELECT；按binding严格有序的接收位置由最新sequence回执承载，没有单独可变游标更新。原量、初始质量、已有input_change触发器及回执一起提交，一处失败全部回滚。

事务语句15秒、锁等待5秒；逐条检查取消/原始授权期限，批次执行超过60秒在下一检查点回滚，最终返回前检查，每32条重验权限。60秒是检查点预算，不承诺正执行的单条SQL立即终止；适配器网络读取仍由244的独立截止控制。

## 并发、恢复与下游

回执ID绑定workspace、binding和确定性planId。两个相同准备只有一次提交；后到者在摘要一致且该回执仍是最新时返回duplicate。不同来源head的过时准备被前回执CAS拒绝，不能回退游标。同计划内容不一致拒绝冲突。成功应答丢失后重新构造协调器，从数据库位置识别current并返回原回执；不会重新创建任务或改成功时间。

任意一条映射/重放/前驱失败、插回执失败、最终撤权或取消都回滚；从原位置重新拉取。原件文件保存仍是适配器在正式入库前的责任，当前内核只验证并保存原件URI和摘要；不声称凭引用就持有文件。

接收成功即产生既有input_change，已登记的派发/重算worker可以在调用方离开后独立消费，并由已有received-data任务工作台追踪。协调器不另建队列、不冒充worker、不在接收事务里强制重算或假报进度。pending数据不会自动变成verified/complete；来源声明仍是unverifiedCompletionClaim，不写source_completion。返回publishesAvailability=false，业务页面截至和固定报告均不推进。

## 数据库与验收出口

空库baseline增加三表（注册修订、head、接收回执），共65表；Prisma只同步标量镜像，无旧库迁移。只通过独立本机随机测试库验证，不对现有业务库应用DDL。运行角色仅增加接收回执INSERT和固定注册读锁函数，无注册/完成声明写权或产品ACL授权。

验证必须使用实际PG运行角色：全事务提交/回滚、重开恢复、同截至修订、乱序与前驱、跨主体重放、范围/租户/配置/途中与最终撤权、取消、并发与过时CAS，及真实input_change到原登记worker/任务监控的链路。内存来源只是本地夹具，不能充当真实来源或平台联调。
