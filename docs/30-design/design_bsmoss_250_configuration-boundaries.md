# 配置管理职责与业务任务分离

2026-11-06。用户要求参考 yucer 管理思路，结合站址分析决策平台业务设计，并要求导航尽量四字。本设计覆盖249中将任务与个人偏好放入配置管理的归属策略；官方DS侧栏布局保持。

## 职责划分

配置管理通过业务Header右侧齿轮进入。配置是长期有效的定义、权限和接入规则，不承担日常更新任务、聚合执行或报告生成监管。个人偏好不改变共享配置。

| 管理组 | 目标内容 | 首批范围 |
|---|---|---|
| 组织管辖 | 责任组织、管辖区域、站址关联 | 后续，不能把平台组织主档当成产品管辖已完成 |
| 成员权限 | 成员角色、操作权限、数据范围 | 后续，延续服务端授权边界 |
| 业务参数 | 指标字典、模板配置、站址分类、分析规则 | 注册字典只读目录；复用原受审模板工作台 |
| 数据接入 | 授权来源、对象映射、更新策略 | 后续，需要真实来源与受审配置 |
| 高级管理 | 配置审计、平台与来源连接验证 | 后续，区别业务执行记录 |

只把可用页面接入侧栏，不创建空入口。管理总览显示五组建设范围，区分“部分具备／待建设”，不伪造权限、接入或上线状态。借鉴yucer职责拆分与DS导航组合，不复制其行业参数。

## 路由与入口

| 内容 | 新地址 | 归属与入口 |
|---|---|---|
| 管理总览 | /settings | 管理侧栏／Header齿轮 |
| 指标字典 | /settings/metrics | 管理侧栏，12项实际注册定义 |
| 模板配置 | /settings/templates | 管理侧栏，既有会话与受审发布控制 |
| 数据更新 | /operations/data-updates | 业务launcher“数据管理”，Header消息／更新面板 |
| 聚合处理 | /operations/aggregation | 数据更新二级入口 |
| 报告任务 | /reports/tasks | 报告中心／业务launcher |
| 总览偏好 | /preferences/overview | 用户面板，仅当前浏览器且按原预览可用条件 |

旧 /settings/operations/{data-updates,aggregation,reports}、/settings/overview、/operations/reports 以固定目标307重定向。保留全部query值与重复项，由目的页原校验处理；不支持外部目标，不静默丢弃错误参数。登录returnTo与跨页任务消息使用新地址。

Header地域在分析列表中改变分析范围；在配置、任务、个人偏好页面只保存全局选择并刷新，不改任务身份或把选择写成任务权限范围。任务授权由服务端决定。

## 字典与布局

字典直接读取 FIRST_METRICS，分类检索、名称／编码搜索、版本／接入状态列表与对象／归属／单位／粒度／聚合／依赖详情。生命周期planned显示待接入；注册定义不等于来源已启用。物理电耗不按运营商重复分摊，温度不可直接相加，比例按累计分子分母汇总。

管理域继续使用已发布ShellViewport、ShellSidebarNav、ShellPageContainer与官方Drawer。业务任务恢复ProductWorkspace及product-page-inset；任务执行逻辑不变。常用导航四字；“运营商用量”保留五字以准确表达业务。

## 后续

下一批按组织管辖／成员权限先建立产品内只读投影与授权约束，再推进业务规则、来源接入和配置审计。平台负责身份组织主档，不等于产品角色及站址范围已完成。本批不改变数据库、API权限、任务生命周期，不接入真实来源、不部署生产。
