# 后台任务进程托管

日期：2026-11-03。接续226。把已有真实授权worker循环打包成独立进程与可选部署单元，不改变业务规则和数据库契约。

## 配置与打包

固定版本JSON宿主配置显式选择aggregate或report、唯一UUID工作区、有限登记ID、执行与历史核验开关、每轮步数／轮询间隔。subject固定为既有s2s:bsmoss，不接受用户输入主体。配置只从显式绝对文件路径读取，32KiB上界、严格字段校验，不含token或数据库凭据、不自动登记任务或授予ACL。

明确开启worker、关闭模拟预览、启用计量功能并配置真实服务client／平台地址／运行数据库之后才启动。OIDC浏览器登录开关与后台服务模式独立。复用现有worker循环和提交前授权，不另开HTTP端口。

esbuild固定到锁中既有0.27.7并声明直接构建依赖。构建单独Node22 CJS，业务依赖打包；pg-native仅作为未使用的可选依赖保留，拒绝PG_FORCE_NATIVE，生产不携带tsx或源代码加载器。同一不可变镜像同时包含Web与worker制品，两个进程分别运行。

## 生命周期与健康

启动与每轮完成原子写入临时目录中的健康文件。状态starting／running／degraded／stopping／stopped／failed，记录版本、PID、规范配置摘要、更新时间与有界汇总，不记录机密、JWT、租户或对象清单。健康命令校验配置摘要、当前进程存活、版本、状态和新鲜度；更改配置需要显式重建进程，不假装热更新。

SIGTERM／SIGINT阻止下一步，等待在途事务／claim边界完成，再关闭自身pool。配置的停机上限到期则非零退出；容器连接关闭由PG回滚未提交事务，独立持久租约按已有机制恢复，不伪造完成。进程日志只输出固定事件和失败类别，不输出原始异常。

## 部署边界

新增可选Compose叠加文件，两个worker共用同一镜像digest和独立私有worker.env，各自只读挂载受审配置。无对外端口、非root、只读根、tmpfs、cap_drop和资源限制。部署／回滚明确选择workers=on或off；on等待全部进程健康，off先停止已有worker，防止旧版本孤留。配置变更随显式交付重建，镜像和worker模式只在readiness成功后记录。禁止在启动时执行DDL。

本地验证包括纯配置／生命周期、脱离node_modules的构建子进程、健康失效及停机等待（Windows进程强制清理，POSIX信号待Linux实测）、既有实际PG事务回归及交付守卫。Linux Docker构建、实际平台注册、自受众票据和机器ACL／登记、Beta网络／真实数据／容量恢复／UAT／生产批准仍需实际完成，不把本地进程验证称为上线。
