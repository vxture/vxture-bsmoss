# 报告生成与导出任务监控

接续217的聚合工作台。本包补齐正式报告队列的查询与追溯：周期生成、导出两种队列按当前实际授权范围查询，查看原登记、尝试历史和精确报告修订，并跳转正式报告重新核验。受审恢复、机器身份与生产托管仍为独立待办。

## 授权与查询

新增独立显式reports.jobs.view，仅登记权限种子、不分配角色。owner、reports.generate／export／export.execute和普通查看都不隐含任务监控权限；监控也不授予报告、发布或下载权限。运维查看者可以不同于原worker主体，不改变机器登记的执行主体约束。

列表使用同只读RR，SQL先过滤完整范围再limit。生成任务使用原登记修订的全部scope，不能只看当前模板已用部分；导出任务使用绑定历史报告manifest的完整requiredScope。包括来源、站址、服务、设备、指标和独立物理站参数开关。每页1–25，requested_at六位微秒及C排序ID倒序，游标绑定kind及status；lookahead同样验证并末次再验权。不存在隐藏租户总数。

详情与列表复用真实生成job、scan manifest、schedule config及导出job／持久报告校验；不重新套当前来源能力来篡改旧任务含义。生成成功结果验证报告模板、周期、摘要及原登记范围。详情最多5条连续attempt，逐项检查终态、失败分类及报告／制品引用。错误或损坏证据不能当作无任务／无记录。

## 生命周期解释

报告生成和导出使用事务内锁、SAVEPOINT及原子回执，没有独立持久租约。监控不会编造“正在执行”状态；数据库时钟只判断pending是否到期，其他为成功或终止。生成任务原登记已被替换时显示登记换版，保留原修订及当前修订，不能把旧pending当作可由当前worker派发。只读RR观察期间发生换版，当前响应仍明确属于其原快照，下次刷新可见变化。

生成结果的revision与执行时currentRevision分别保存和显示，旧输入幂等重放不能冒充最新修订。导出任务只知道其绑定报告revision，不编造当时最新生成修订，currentRevision返回null。导出成功只表示当时制品已写入，不承诺当前报告仍活跃、完整、新鲜或可下载；这几项由原正式报告／下载接口重新核验。

## 页面与接口

新增GET /api/report-jobs及/{id}?kind=generation|export，使用真实RP组合根、平台权益、独立权限与事务返回前原／当前主体、租户、有效期及完整范围复查。严格筛选、重复query拒绝、no-store／nosniff／Vary Cookie、固定错误，不开放worker执行或租约内容。

/operations/reports提供双队列切换、状态筛选、分页、宽详情及执行时间线，无默认任务。与周期报告和聚合工作台互通；窄屏保留导航。结果链接使用/reports?report=...&revision=...，显式准确修订且支持大整数；非法／重复参数不选择报告，无链接时仍无默认选中。登录returnTo保留合法链接，但不能绕过后续API授权。

空库基线仅新增独立权限种子和两队列各两个历史索引，仍为56表。Prisma标量镜像不变，无旧库迁移。原调度、生成、发布、导出执行及重试语义保持原契约。
