# 历史报告周期核验与修订

登记日历处理近期到期窗口；已有较早报告的数据／质量／权威／逐日依赖变化，不能永远停留在stale。本批增加显式开启的历史核验通道，复用当前受审登记与真实机器授权；覆盖该登记模板版本、粒度及notBefore之后已经存在并已到期的报告。未生成过的历史周期仍走受审补跑，不任意枚举无限历史。

每步一个报告，完整历史scope先SQL过滤再LIMIT；从未核验优先，其次最久未核验，再按周期和ID稳定排序，以当前登记修订＋小时＋reportId的不可变回执排除本小时已核验报告，不使用会越过晚提交事务的全局游标。跨小时积压也不会反复从最早周期开始而饿死后续报告；last-check索引支持登记内选择。每次新事务重查，进程重启继续未处理项；同小时核验之后才发生的变化，下一小时开始可再次核验。hourly是最早重查边界，积压仍按上述顺序处理，不承诺一小时扫完全部历史，也不宣称实时通知或11万站规模性能。

工作事务持有登记head共享锁，验证active、固定subject、完整scope、原模板SHA及generate权限。读取原current报告并核验完整manifest，按既有正式读取逻辑检查最新单对象／区域／逐日依赖。current则追加unchanged回执；stale则在同一RR事务调用既有生成核心，保存inserted或duplicate及准确result revision和当时current revision。旧报告和发布事件保持不变，不自动发布；新报告仍可明确缺数或stale，不能把一次重新生成称作修复完成。

已知映射／区域绑定不可用可记录blocked，保留原版本并允许其他报告继续；不制造零值或来源证据。SQL故障、摘要损坏、权限和范围拒绝、序列化／死锁、未知异常均整体回滚，不写成功或blocked回执；宿主已有独立通道退避，下一事务重试。核验／生成／head／outbox／不可变回执／末次真实授权同事务提交。

新增report_history_check，主键为租户＋登记＋登记修订＋scan_hour＋reportId；精确原修订、结果修订／SHA、当时head同租户外键。manifest绑定配置与日历摘要、核验时间、原报告、核验结论／原因、结果和完整历史／新scope并集。数据库触发器验证当前登记主体、报告模板和窗口及真实head，捕获DB SHA／session_user／时间、禁止改删清空；应用完整JOIN和双SHA读回。新产品只变空库baseline和Prisma标量镜像，无迁移。

ReportWorkerConfig显式reconcileHistory=true才增加独立轮转通道；每登记普通生成与历史核验互不饥饿，最多32登记加一个导出通道，沿用65通道总上限。未显式开启时保持当前日历行为。此配置不能创建身份或授权，真实provider／生产托管仍依平台契约。

验收覆盖72小时外变化、日周月及逐日单独修订、未知／未接入／完整性保持、同小时幂等和下一小时重查、晚提交报告、并发竞争／旧RR、历史全scope／物理参数、暂停换版、写后各类撤权和SQL回滚、blocked不阻塞后续、来源损坏不吞错、不可变证据与跨租户FK。真实接入、Beta、容量／恢复／UAT和生产批准仍需实际环境验证。
