# 周期刷新持久任务与租约

2026-11-02。I09第二批，在已有自然窗口规划之上实现内部队列与单步执行，不启用生产定时进程。

## 稳定身份与触发

任务身份使用workspace、来源、稳定对象、指标版本、自然粒度、完整窗口及可信triggerRef，以refresh-job-v1生成摘要。映射anchor仅用于再次加载对象，不纳入任务业务身份；相邻映射下同对象同触发重复入队只生成一项。

triggerRef必须来自可信调度器或证据修订标识，不能用任意客户端时间戳代替。日历扫描应使用可重放的扫描标识，历史修订应保留事件／质量／完成证明的修订引用。新修订生成新任务，完成或死亡任务的相同触发重放不复活；人工重试须有新的审计触发引用。本批不实现触发器来源、调度游标或outbox消费确认。

纯`planRefreshJob`仅接受已授权可信快照，核对目标来源、指标、粒度与自然窗口；队列不接受事实、确认标记或任意水位。内部适配器仍需调用者先完成授权，尚无公开入队／消费HTTP入口。

## 队列与租约

新增refresh_job保存不可变任务身份及可变队列状态，refresh_attempt保存不可变执行回执。队列按workspace及明确的来源／对象／指标三元组过滤，授权清单有界。INSERT唯一键实现原子去重；SELECT FOR UPDATE SKIP LOCKED使并发消费者取得不同任务。

状态为pending→leased→succeeded，失败回pending或达到上限后dead。每次租约使用新UUID token和递增attempt，5—900秒；默认5次，允许1—8次。失败按5、10、20……秒延后；错误仅存受限代码，不记录原始异常和密钥。任务过期由后续claim写入expired回执并换token接管，末次租约过期则dead。没有消费者时不会自动扫过期任务。

续租／完成／失败均先锁行，再按数据库clock_timestamp核验token、attempt及有效期；不能依赖调用者时钟或进入事务之前的时间。锁等待之后已经过期也拒绝完成。运行角色只允许更新状态、attempt、token、租约与调度时间，不能修改任务身份、目标或尝试上限；尝试回执不可修改删除。

## 与聚合原子提交

`executeRefreshLease`每次执行重新解析平台能力、产品aggregate权限及有限数据范围，再读取最新可信快照和结果head。只处理现有区间计数／依赖／比率入口，瞬时与状态不因进入队列而自动获得支持。

带租约的PgAggregateStore先核对对象／指标／窗口，再锁定同一任务租约。聚合修订、current指针、aggregate outbox、成功回执和任务succeeded在同一事务提交；重复输入也在同一事务确认已有结果引用。提交前再次核验有效租约，失去租约不写结果，回执失败则整体回滚。expected-head冲突不确认任务，下一次单步执行重新读快照和head。

后续196设计补齐了授权批量入队、就绪候选与单步失败分类，并将输入／head／写入纳入同一事务。真实机器身份、登记分区／对象枚举、长期运行循环、续租策略、日历扫描游标、输入证据事务outbox及自动旧／新作用域传播仍待完成，不能称正式调度服务上线。
