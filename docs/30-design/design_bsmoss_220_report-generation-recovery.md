# 周期报告生成任务受审恢复

延续独立reports.jobs.recover权限，恢复者不必是登记worker；新任务仍归原登记subject执行，审计单独记录复核者。原失败任务、连续尝试和原扫描清单保持不变。

新任务携带recovery_of和scan_job_id；普通扫描任务两者为空，原扫描窗口唯一约束改为仅普通任务的唯一索引。恢复任务通过同租户自引用和延迟外键必须关联已提交恢复审计，不能仅插入伪造任务绕过原扫描清单。审计绑定原job、精确dead attempt、新job、原始扫描root、原登记摘要、完整scope、复核者和依据；数据库触发器校验绑定并禁止改删清空。Prisma仅镜像，仍为空库baseline，无迁移。

执行与监控共用来源验证：原扫描manifest必须包含scan root及精确周期／dueAt；恢复审计必须完整验证旧新及root绑定、双SHA、精确终态和原完整登记scope。恢复任务也必须通过当前登记固定worker、权益、generate权限和完整scope，成功报告／outbox／attempt／job仍同事务，不能借恢复自动发布。

首次恢复必须原dead／expectedAttempt一致，当前登记共享锁及原修订一致、active、原模板摘要仍受审有效；禁止改绑新登记、换subject或修改原扫描。每原job一次恢复，新job再次dead可继续链式复核。精确命令重放按原actor／reason／attempt和历史scope重新验权，今天登记暂停或换版不改变旧回执；后续执行仍独立拒绝。

同一恢复接口接受显式generation或export，两种命令与证据隔离。工作台提供两类任务的恢复链、复核依据和不确定响应同命令重试。验收包括普通扫描唯一性不变、孤立／跨租户／伪造恢复拒绝、真实执行／链式恢复、暂停换版、并发登记fence、各阶段撤权／SQL回滚、精确幂等重放和宽窄屏。真实机器身份、来源接入及生产上线仍属外部与后续验收。
