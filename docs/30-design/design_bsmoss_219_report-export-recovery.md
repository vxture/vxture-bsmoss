# 报告导出任务受审恢复

导出失败恢复采用独立的 `reports.jobs.recover` 权限。查看、执行、请求导出、下载与工作区 owner 均不隐含该权限；只加入权限种子，不自动赋权。

恢复保留原 dead 任务和全部尝试，按原报告、发布事件、报告修订、摘要和渲染器建立新的 pending 任务。每个原任务最多一次恢复，新任务再次终止后可继续形成恢复链。不会重新发布报告或立即授予下载。

首次恢复必须核验完整历史 scope、连续终态尝试及 expectedAttempt，锁报告系列以沿用发布事务 fence，然后核验精确原发布仍活跃、报告完整且新鲜、渲染器仍受当前构建支持。撤回、替换发布或旧渲染器均不得自动改绑。原子提交新任务、不可变恢复审计及提交前真实身份／权益／独立权限／实际范围复查。

命令重放按原 command、actor、reason、原任务及终态尝试精确匹配，重新核验历史完整 scope 和当前真实授权，返回原回执，不重新套今天发布状态。此举仅确认已提交命令，执行和下载仍独立检查当前可用性。

空库 DDL 新增恢复证据表和同租户精确终态外键；固定 search_path 的 invoker 触发器校验旧新绑定、原 scope、命令与主体，记录数据库 SHA、session_user、数据库时间，拒绝修改、删除、清空。Prisma 仅作标量镜像，无旧库迁移。

POST 使用配置 origin、实际流 16KiB 限制及严格 JSON／路径校验。工作台提供父子任务导航、审阅依据和明确反馈；503／网络不确定保留原命令重试，明确拒绝后重新读取。生成任务恢复需独立保留扫描来源和唯一性，不纳入此包。

验收覆盖独立权限、全 scope、真实 dead 历史、成功执行下载、精确重放、竞争／发布 fence、撤权／SQL 回滚、审计篡改和跨租户外键，以及宽窄屏和同命令重试。当前仅本地验证，不代表真实平台注册、接入、部署或上线。
