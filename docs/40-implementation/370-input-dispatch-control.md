# I09 输入消费失败退避及隔离

2026-11-02。设计见 [输入消费控制](../30-design/design_bsmoss_201_input-dispatch-control.md)。内部服务，不开放页面／HTTP或生产后台身份。

## 交付

- input-dispatch-control：受限错误分类、5次重试、指数退避与显式恢复后的计数。
- pg-input-refresh：同事件／订阅围栏、独立全历史范围验权、工作 SAVEPOINT、追加失败记录、按数据库时钟发现、单步监督和带依据的 CAS 恢复。
- 空库基线 input_dispatch_event／Prisma 标量镜像，共36表，运行身份无 UPDATE／DELETE；没有旧库迁移。

失败不会确认消费，不留下半批任务。任务／消费回执故障、授权过期、范围改变或失败账本自身写入故障全部回滚；错误文本不进入账本。历史对象验权不受1000条证据返回边界限制，历史映射缺失等规划错误可以退避和隔离。隔离后保留原证据，显式重新验权、预期修订和恢复依据才能再次处理。

## 验证

新增4项单元测试覆盖次数／修订上界、退避序列、受限分类及无权限时零数据库访问；实际 PostgreSQL 回归覆盖原子回滚、延迟发现、配置分区、5次隔离、恢复幂等／冲突、后续正常记录继续、撤权／过期／范围变更、账本故障、并发计次、运行角色不可变／租户约束，以及超长修订与缺映射规划错误。最终通过数量和制品检查点以 agent 收尾记录及 artifacts/formal-checkpoints/input-dispatch-control.json 为准。

本地测试仅建删专用 PostgreSQL 上随机 bsmoss_contract_* 数据库；不会向真实来源写完成证明。无 UI／依赖变动，不重复不变的六场景浏览器验收；最终类型、生产构建、HTTP、Prisma、文档／镜像／交付／SCA配置及源码／密钥扫描记录在同一检查点。
