# I08 可信快照与聚合服务编排

2026-10-29。延续 yucer 的规则、服务、store 和运行组合根分层，补齐直接区间增量与直接比率的内部授权编排。没有新增 HTTP 路由、任务身份、来源连接器或生产部署。

## 授权入口

createAuthorizedAggregates 每次调用重新解析可信身份、平台覆盖、产品功能及本地授权，使用 metering.aggregate 操作。owner 的既有 view/ingest 基线不扩展到 aggregate；必须明确授予此权限及有限对象范围。没有默认后台超级身份。

请求只选择 sourceId、mappingId、metric、grain、at 和 expectedRevision；不能提交租户、主体、原始输入、来源权威、水位或完整标记。嵌套指标也只允许 code/version。请求在等待身份解析之前复制，避免异步期间被调用者修改。

PgAggregateSnapshotReader 从本地有效授权创建，每次读取校验来源、指标、站址、服务/设备及物理参数权限。读取后再次检查授权到期时间，再按服务端生成的唯一来源/主体/指标三元组创建 PgAggregateStore，发布人来自可信身份。到期检查发生在发布前；不宣称撤权与已开始的数据库事务具备跨系统原子性。

runtime 的 aggregatesForSession 复用现有 RP/C2/本地 grant 适配，没有重复定义平台协议。它目前仅是服务端组合函数，无路由调用，因此不能将本批视为已经开放生产聚合接口或完成平台注册联调。

## 来源能力与适用范围

当前只接受 interval_delta 和直接 ratio，不自动将 total_bytes 或依赖计数拼成派生计划。来源能力必须为 active、有非空 validation_ref，且完整覆盖目标周期；同来源同指标出现两个重叠 active 能力时拒绝。

能力的 rules 使用产品内部审阅配置：

```json
{
  "intervalAggregation": {
    "version": 1,
    "inputMode": "direct",
    "authorityRef": "reviewed-source-authority-reference"
  }
}
```

这只是产品内部能力策略，不是新的平台接入 wire 协议。配置由受控管理路径录入，运行角色无权修改；示例不激活任何真实来源。缺少配置时拒绝，而非根据样例推断权威。

mapping、来源能力和服务关系必须覆盖整个自然周期。同一来源同一物理主体若存在多个时间重叠映射别名，也拒绝自动选择或相加。主体键为版本化 JSON 元组：站址、服务关系、网络对象、设备；不依赖含斜线的自由拼接。authorityVersion 摘要绑定策略、映射 ID/版本、能力 ID 和验证引用，输入清单保存对应计划。

这种约束先完成单一稳定映射的可验证切片。跨映射切换、服务中途生效/失效、混合频率或多个别名的显式权威选择需要后续适用窗口规划器；当前拒绝，不输出虚假的完整值。不同来源各自保留序列，跨来源去重仍待明确权威策略。

## 一致输入快照

映射、来源能力、指标标量定义、事实和质量结论在同一 REPEATABLE READ READ ONLY 事务内读取，不复用证据下钻 list 接口。后者保留初始质量结论，语义不同，保持原样。

事实按租户/来源/事件/组件/指标版本取最新修订，再判断其所属映射和窗口。若修订移到其他窗口或对象，旧事实退出原序列，不能回退计入。每条最新事实按 quality_decision.revision 取最新质量；pending/rejected 保留到输入中，由规则明确缺数原因，缺少质量结论则拒绝整个快照。

查询使用窗口相交条件，避免把横跨边界的数据静默丢弃；纯规则再验证完整原生窗口、重叠和类型。单次最多 100000 条事实，超过即失败，不截断成看似完整的结果；授权列表各最多 10000 项，省级运行需分批分片，不能一次读取全省明细。

尚无来源完成账本。plan.watermark 固定为目标周期起点，sourceComplete=false；已齐的直接输入最多标记 preliminary，缺采仍为 partial/missing。不能把最大采样时间或全部行存在当作来源完成证明。

读取事务与结果发布事务分开：发布使用一致的输入快照及 expectedRevision 防止聚合指针并发覆盖，但不保证保存瞬间来源没有新事实。新输入及质量修订的持续传播、重算排队由 I09 完成，当前不会自动刷新已保存结果。
