# I08 来源完成确认、水位与撤销证据

2026-10-29。本批完成独立完成证据账本及聚合读取，覆盖此前“所有结果最多 preliminary”的限制。没有开启来源连接器、确认写入接口或后台任务，真实来源的确认协议仍待 D05/I06 核验。

## 完整结果的成立条件

直接区间/比率结果同时满足以下条件才可由本快照链路产生 complete：

1. 来源能力、权威配置、映射和服务关系覆盖整个目标周期，授权范围校验通过。
2. 最新来源确认是 confirmed，且确认绑定的输入指纹与当前快照一致。
3. 确认水位不早于目标周期结束。
4. 所有适用原生窗口均存在合法、最新且 verified 的输入。

确认只证明来源声明和指定快照的绑定，不替代测量质量核验。来源确认即使覆盖缺数快照，结果仍是 partial/missing；无适用窗口仍为 not_applicable，零分母保留原因。不能把确认当作自动质量批准。

## 账本与写入边界

空库基线增加 bsmoss_integration.source_completion，共 30 表，Prisma 同步标量镜像。只修改首次初始化基线，无旧库迁移。

账本按租户、来源、映射、指标版本、粒度及完整时间窗保存正整数修订；另保存 confirmed/revoked、输入指纹、水位、原始确认引用及 SHA-256、录入主体和录入时间。同租户映射/来源/站址复合外键、唯一键和数值/摘要检查由 DDL 约束。

运行身份只有 SELECT，不能写入、改写、删除或清空完成账本。未来连接器必须先核验来源完成声明的真实性和授权、确认相关批次已提交，再通过受控写入路径生成与本地输入快照一致的绑定。当前没有提供运行账号的确认权限，也不向普通用户开放“标记完整”按钮。测试中的管理身份录入仅为合同测试，不代表真实来源签认。

账本使用最高 revision 作为最新决策，不按到达时间覆盖，也不退回较早的匹配确认。撤销以新修订追加，保留旧确认；管理路径需分配修订并记录审阅依据。DBA 作为数据库所有者拥有维护能力，运行权限限制不等同于对 DBA 的不可变保证。

## 输入绑定和算法版本

bindSourceCompletion 先以同一指标、对象、周期、原生粒度、来源权威、最新测量及质量修订计算基础快照。基础计划固定 sourceComplete=false、watermark=周期起点，并排除 completionEvidence，避免自引用摘要。

确认记录中的 input_fingerprint 引用该基础指纹。它不是来源原始文件的 SHA-256；evidence_sha256 才是原件摘要。不能把原始批次摘要直接填作本地输入指纹。

匹配 confirmed 时使用确认水位及 sourceComplete=true；否则使用周期起点及 false。最新撤销加入 source_confirmation_revoked，过期绑定加入 source_confirmation_stale；结果和输入清单保留确认修订、状态、水位、原件引用和摘要，后续可定位账本。

事实、质量、映射/转换版本、来源权威或算法变更都会影响基础指纹。纯规则再次核验绑定，拒绝把过期证据搭配 sourceComplete=true 的计划；相同输入重排和重复不改变绑定。

本批聚合规则版本升为 bsmoss-periodic-v2，明确新指纹契约。没有改写历史快照或运行数据；若后续需重放旧算法版本，应保留对应实现和构建，当前 v2 不能声称自动解释任意历史 v1 指纹。

## 一致性与修订传播

完成账本与映射、能力、事实、质量在同一 REPEATABLE READ 快照中读取。读取开始后才提交的确认不会混入本轮；下一轮才可见。结果发布仍使用既有 expectedRevision 及原子结果/指针/outbox 事务。

新的完成确认、撤销、事实或质量修订不会主动刷新已保存结果。本批只保证再次重算时正确读取和降级；自动重算触发、事件消费、过期结果提示及报告依赖失效仍归 I09/I11/I12。历史 complete 结果表示其引用时点的快照，不能据此宣称它仍是最新来源结论。

当前账本针对单个映射、指标和目标粒度，不自动将小时确认合并成日/月确认，也不跨来源、跨映射或依赖派生沿用。跨映射有效窗口规划、依赖完成证明、瞬时/状态结果版本存储仍待实施。
