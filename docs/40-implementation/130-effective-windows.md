# I08 跨映射与服务有效窗口规划

2026-10-29。本批在现有可信快照链路增加有效窗口规划，解决周期内切换映射及服务中途生效/失效的情况。沿用 rules/service/store 分层，无 DDL、依赖、迁移、前端或部署变更。空库仍为 30 表，I08 保持 in_progress。

## 主体与授权边界

请求中的 mappingId 用于定位一个已经授权的稳定主体。服务端在同一租户、来源、站址、服务关系、网络对象及设备元组内查找时间相交的映射，按有效期规划。mappingId 是查找锚点，不要求锚点自身覆盖整个报告周期。

不同服务关系、运营商服务归属、网络对象或设备不会自动合并。若映射切换同时更换主体，分别保存各主体结果；跨主体汇总仍需权威与互斥规则。来源、站址、指标、服务及设备权限在规划前检查，相邻映射必须与锚点具有同一主体元组，不额外扩大授权。

映射 ID 和输入事件的 ID 不是同一种去重键。输入仍按来源/事件/组件/指标的最新修订选取，再判断其当前归属。修订移到另一个主体或窗口时，原记录退出原结果，不回退旧版。

## 适用窗口规则

planMappingWindows 是纯函数，输入自然周期、统一原生粒度、同主体映射有效区间，以及可选的服务有效期。输出 applicablePeriods 和逐窗 mappingWindows。

服务有效时段与目标周期取交集。只有完整落在有效服务时段内的原生窗口才适用；服务不在周期内时返回空清单，聚合为 not_applicable，值为 null。物理站址指标没有服务关系时，按完整目标周期规划，不根据“缺少映射”推断它已停用。

每个适用窗口必须恰好由一个有效映射完整覆盖。相邻映射可在原生边界切换；映射重叠、有效时段内有映射缺口、边界落在原生窗口中间均拒绝。不会把缺少映射的时段从分母偷偷删除，也不会把区间计数均分到切换点两侧。

例如，小时内服务仅在 00:15–00:45 有效，原生粒度 15 分钟，则预期 2 个窗口；两个窗口都有合法输入时不记 missing_windows，少一个仍为 partial。原生粒度为小时，服务在 00:30 生效，则拒绝拆分该小时。映射在 00:30 相邻切换且原生粒度 15 分钟时，四个窗口分别属于旧、旧、新、新映射。

规划按映射起点排序、检测重叠并顺序扫描窗口；映射及窗口各最多 10000 项。查询超过映射上限直接失败，不截取前一部分生成结果。来源能力仍要求唯一、active、已审阅且覆盖整个报告周期；跨能力版本或混合原生频率暂未规划。

## 输入核验与版本留痕

PgAggregateSnapshotReader 在同一 REPEATABLE READ 快照中读取相关映射及最新事实，输入记录带上真实 mappingId 和 mappingVersion。规则层校验每条选定事实与所属窗口的映射 ID/版本完全匹配，跨有效期、冒用别名或落在服务未生效时段的事实会拒绝，不静默丢弃。

结果增加逐窗映射清单，证据引用增加 mappingId；已有 input_manifest 保存完整计划与输入。来源权威摘要同时绑定排序后的相关映射 ID、版本、起止时间及服务有效期。不同锚点得到相同的主体、计划和指纹，发布到同一 series，重放不重复计量。

mappingWindows 为可选字段，纯规则仍能执行此前无清单的内部计划；新快照读取器始终提供清单。此次保留 bsmoss-periodic-v2，新增字段参与指纹；旧确认不会自动套用新计划，重算必须匹配新基础快照。结果旧版本不被改写。

## 完成确认限制

单个有效映射的结果继续使用该映射的最新来源确认，与适用窗口及服务有效期一起绑定。已有确认因映射边界、服务生效期或输入变化而失效时，需要重新确认。

周期内实际使用多个映射时，当前单映射 source_completion 账本不能表达组合证明，因此不读取单段确认作为整个组合的完成证据。有效数据齐全时结果仍为 preliminary，缺失时为 partial/missing；不制造 complete。组合完成证据与撤销传播是后续任务，不能用任意锚点的确认替代。
