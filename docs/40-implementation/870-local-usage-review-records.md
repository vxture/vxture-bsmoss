# 用量核验第四切片：本机人工记录闭环

2026-11-05。用户“继续下一批”，接续BA01–BA04后的B01-04。业务依据为[规格90](../20-specs/90-usage-verification.md)与[设计235](../30-design/design_bsmoss_235_usage-verification.md)。

## 已实现

用量核验详情支持原因确认、复核通过、退回及重新打开。所有动作追加事件，保存原因、说明、本机记录时间与当时完整证据；状态由事件折叠，不能任意指定。核验记录独立列表仅显示实际发生人工动作的对象，支持状态、原因、周期、指标、运营商及Header地域，进入同一详情定位事件并展开原证据。状态筛选在分页之前完成，刷新及重新打开页面后保留。

仅在显式preview下使用UV隔离场景库bsmoss-demo-review-scenarios-v1。HE经营历史只读依据不转成UV案件，也不把场景测量写入地图、报告或正式测量。记录标识“演示记录·本机”，操作者固定演示访客。它是本浏览器的操作记录，不是正式业务签认或服务器审计。

纯规则、service及IndexedDB adapter分离。严格命令只接收命令ID、对象、期望版本、证据引用、动作、原因及说明；拒绝客户端身份、工作区、目标状态、时间与测量替换。同一事务核对活动会话、记录版本、命令回执并写入事件与回执，transaction.complete后才提示成功。旧命令重放返回原事件，不倒退当前状态；同ID异内容拒绝。两个标签同版本只允许一个动作提交。

确认和复核绑定当前证据，旧确认不能直接通过新依据；重开后需重新确认。旧事件保存原证据快照及精确整数，不将旧链接指向最新量。事件schema、状态链、固定actor、数据集/会话与可重算证据损坏时只读失败，不静默重建。存储不可用、配额或事务失败不显示假成功；结果未知时沿原命令重试。BroadcastChannel及focus重新读取权威本机记录，编辑中的旧草稿被锁定，不能自动改为另一个动作。

“开始新会话”只切活动指针，旧会话可回看且不可追加；不删除历史。会话选择在列表、详情及核验记录往返保留，URL会话UUID与事件号严格校验。preview关闭不初始化存储，核验记录404；未增加匿名写API、正式权限、依赖、DDL或PG表。

独立loopback原生IndexedDB测试页运行17项检查：并发初始化、同版本竞争、提交后可见、精确旧命令重放、ID冲突、注入写失败及整体回滚、同命令重试、旧证据禁止通过、原快照保留、关闭重开、数据集隔离、新会话归档、归档禁止追加、损坏显式失败及新会话独立。测试使用唯一数据库，不改应用或正式数据库；证据artifacts/review-records-qa/idb-contract.json。

实际页面走通确认→复核→重开→再次确认→退回，刷新后保留五条历史；第二标签编辑复核草稿时第一标签完成复核，第二标签锁定原动作并提示重新核对，未自动变成重开。记录列表只显示一个实际操作对象，并能定位第五事件和原始证据。会话归档、空态及最终截图/日志以本批检查点和最新memory为准。

本轮浏览器viewport接口返回成功但实际页面仍为1280宽，早期拟命名mobile的截图不算窄屏证据；仅记录实际尺寸，904/390响应式待复核。未声称完成B01整体验收。
