# I04 数据持久化适配器验收

日期：2026-10-28。交付范围：原始证据、类型化测量和首次质量决定的事务写入与受限证据查询。
不包含来源连接器、周期聚合、配置持久化或生产身份解析。

## 代码入口

- domains/measurements/store.ts：新测量端口、三类值类型、可信数据范围与分页契约。
- rules.ts：规范整数、numeric上限、时区/毫秒精度、指标语义、比率及状态有效期检查。
- service.ts：能力门、操作权限、工作空间及质量决定身份校验。
- pg-store.ts：参数化SQL、事务、自然键幂等、冲突拒绝、映射有效期及范围控制。

采用node-postgres执行具体SQL，以便精确控制INSERT ON CONFLICT、权限与多表事务。
Prisma仍为结构镜像，未生成client，也未增加第二套结构管理路径。
旧metering/MemoryUsageStore为早期测试示例，数据库没有对应旧usage_record表；
不将新测量模型强行塞进旧秒/字节端口，真实接入应调用新服务。

## 写入契约

store构造时快照化可信workspace、source、station、metricKey、service、device范围及
站址物理参数访问开关；请求不能提供自己的授权。服务上下文与store工作空间必须一致。
主体范围通过经过授权的serviceIds落实，设备和站址物理参数需另外授权，不由站址服务关系自动继承。

对每条记录：先克隆并验证输入，再读取有效映射与指标定义，之后在同一READ COMMITTED事务中
写raw_event、measurement及quality_decision(revision=1)。任一步失败回滚，连接归还；
回滚失败时销毁连接，避免后续请求复用异常事务状态。

自然键重复时在数据库比较全部不可变业务字段；一致返回同一measurement ID，冲突抛出
conflicting_replay，不覆盖原值。received_at、数据库生成id和决定时刻不参与重放比较。
时间统一成UTC毫秒，超出毫秒精度拒绝，避免JS精度截断造成错误幂等。
数字仅接受规范十进制字符串，拒绝小数、指数、前导零及越界，不依赖数据库舍入。
修订使用新的revision并关联前版；已存在版本不修改。

first-batch字典支持integer_delta、ratio_parts、state_event持久化；fixed_point有存储表示，
当前字典没有合法指标，因此写入不会启用它。派生总流量也不作为直接采集记录写入。

## 查询契约

每次强制workspace、source、station、metric、service/device范围；metric无权时拒绝，
行范围不匹配不返回数据。列表需时间窗，最长31天、每页1–200条，按稳定id游标分页。
只返回完整包含在查询窗内的源记录，不对跨边界记录擅自拆分。
该接口是证据下钻：保留全部源修订，返回首次质量决定，不代表当前有效质量或可直接求和的用量。
当前不提供分页全程一致性快照；分页期间新增记录可在重查时看到，正式报告应固定输入版本。
