# 受审设备状态与均温分布实施

接续 d29ae0c，设计见 [223](../30-design/design_bsmoss_223_reviewed-device-distributions.md)。I08 本包完成有限物理设备总体的状态和均温分布，分层规模汇总及全省容量验收仍待推进。

## 业务实现

object-rollup 依据指标语义分派到新增纯规则 device-distribution。设备总体必须显式包含 deviceId、真实站址及空服务／网络对象；每成员一个设备，跨来源、跨站重复设备及重叠覆盖均拒绝。复用原受审追加配置表和只读运行权限，总体上界 256、成员上界 64 不变，没有新增表或旧库迁移，原区间结果结构和指纹没有增加字段。

状态输出六态期末数量及设备毫秒，总体、成员和未知时长守恒；部分设备的期末未知不抹去之前真实已知时段。温度按每台设备自身周期均值进入经审阅区间，明示均值 mode／scale／阈值依据，边界以 BigInt 精确分数比较，不跨设备求平均或求和。来源均值计算分数可以超过单个来源值 30 位，另设 64 位计算字符串上界。无温度数据也先核对真实来源均值策略，不能借未发布绕过口径错误。

新增 distribution 有类型字段及逐设备 deviceValue，scalar value／knownValue 均为 null。未覆盖、未发布、来源不可用、权威 generation 漂移及过期发布归入未知；已知子集不等于整体完整。配置权威失效后，即使能力改回旧值并重新发布，也须追加新的审阅配置才能恢复贡献。不会推断站址停运／退役影响或运营商电耗分摊。

## 正式服务与展示

同一个 RR 读取配置、完整真实设备总体和成员可信当前发布。设备授权独立于站级参数开关和运营商服务范围，含未覆盖设备。授权错误、SQL 错误和证据错误不转缺数。正式报告 requiredScope、分析隐藏目录与个人偏好历史均携带真实设备范围；生成提交、发布、执行导出及下载仍重复验权。

既有 /api/aggregates/rollups 选择器不变，未加入客户端传总体／阈值／值的入口。正式分析通过服务端模板使用分布卡片，展示总体、有效数据覆盖数、完整性／新鲜度与精确依据；分布没有单值折线。显示格式与正式报告／HTML 共用，周月固定逐日分布证据；输入修订使旧报告 stale 且拒绝旧制品下载，历史内容保持不变。原已支持区间和单设备的 HTML 输出字节未改；新分布输入此前不受支持，未变更既有渲染版本。

浏览器检查发现全局 dl 样式给每行附加 20px 外距，已在分布组件内归零并固定局部字体，避免无意继承地图样式。未修改主地图布局、默认站址、地域范围或底图。

## 验证

512 项单测、334 项实际 PostgreSQL 检查、双层类型和生产构建通过；最终 20 项 HTTP、119 篇文档／59 表镜像及交付／SCA 守卫、ASCII、密钥扫描与运行 SHA 以 reviewed-device-distributions 检查点为准。无依赖或 DDL／Prisma 变更，沿用上一包已通过的 Prisma CLI；实际 PG 仍从同一 59 表空库基线建立随机合同库。

新增七项纯规则测试验证设备时长和期末数守恒、重复总体／来源、未知及过期、负数和精确分数边界、超单值长度计算、策略／阈值拒绝、顺序稳定指纹、显示单位。新增八项实际 PG 场景覆盖真实三设备／两站总体、完整设备授权、无数据策略校验、报告生成→发布→导出→下载、历史设备撤权、隐藏不读时序、日周月依赖、写后撤权回滚、SQL 错误、并发统一快照、旧报告不变和权威恢复需重审。

首轮新夹具把状态事件 periodEnd 固定为整日，但 validUntil 仅半日，被 invalid_state_expiry 正确拒绝；改事件窗口匹配有效期。随后分析夹具把仅允许 state 单位的 card 配为 device_count，被 state_view_unit_mismatch 正确拒绝；修正夹具为合法 card 单位。产品规则没有放宽，最终 334 全过。

独立 63334 合成 API 加实际 React 组件进行桌面与 390×844 窄屏验证，11 行分布与总体覆盖可读，没有多出的标量趋势或浏览器警告／错误。桌面 client／scroll 均 1265、手机均 390。截图和 state.json 在 artifacts/device-distribution-qa；视窗已 reset，临时 tab13 已关闭。合成组件验证不代替正式平台接入或客户验收。
