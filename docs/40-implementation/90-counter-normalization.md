# I07 第一批：累计计数标准化

2026-10-29。沿用 yucer 的纯规则、服务、store 分层，本批实现 `domains/normalization/counters.ts`。
这是可独立验证的来源标准化规则，尚未接入正式连接器、证据存储、隔离队列或 HTTP 入口。
I07 标记 in_progress；D05 的授权来源样例和口径签认仍是实际接入前提。

## 处理范围

支持首批字典中 interval_delta 类型指标的累计来源，包括通话秒数、呼叫/短信次数、流量字节和电量。
不能将接通率、设备状态或双向派生总量当作累计计数。
规则先生成候选规范增量，再交给后续可信质量与持久化服务，不能直接把候选值写为 verified。
费用计算、数据库迁移、设备控制和自动来源激活均不在本批范围。

## 输入契约

`CounterPolicy` 是服务端解析的来源能力快照，固定 workspace、source、subjectKey、指标版本、
能力证据引用、映射/转换版本、有效期、原生窗口、原单位与规范单位、精确换算系数。
若来源计数器可能回绕，必须声明独占上界 modulus，例如 32 位计数器的 modulus 为 4294967296，
而不是最大可读值 4294967295。maxRawPerSecond 是来源能力确认的物理上限，不是产品猜测阈值。
来源/对象/方向、映射与统计口径必须先由服务确定，客户端不能提供这些可信配置。

每条读数保留事件 ID、测量修订、质量修订、质量结论、原始累计值、原单位、采样时间、
计数器安装/连续性 epoch、载荷摘要及映射版本。只有同 workspace/source/subject/metric 的读数可进入同一次计算。
映射版本不匹配或计数器 epoch 变化会形成待核验边界，不跨换表、换对象连续差分。

转折证据分两类，均需要证据引用并绑定前后两个读数的事件、测量修订和质量修订：

| 证据 | 所需事实 | 运算 |
|---|---|---|
| wraps | 精确回绕圈数，允许明确的 0 圈 | 当前值 − 前值 + 圈数 × modulus |
| resets | 按时间排序的每次复位时刻、旧计数终读、新计数初读 | 逐段累计复位前增量和复位后增量 |

复位证据必须说明实际旧表终读和新表初读；仅知道“重启过”或“清零过”不足以恢复整个区间用量。
规则只验证证据结构、版本绑定和数值一致性；证据签名、来源授权和真实性由接入服务核验，引用字符串本身不是授权证明。

## 决策语义

返回 baseline、eligible、pending 三种状态；value 只在 eligible 时出现，其他情况为 null。

| 场景 | 处理结果 |
|---|---|
| 首次读数 | baseline，建立参考点，不把累计历史读数当作本期用量 |
| 连续两次有效读数相同 | eligible，真实增量 0 |
| 普通累计上升 | 在原生窗口、有效期、映射和质量都满足时差分 |
| 无依据下降 | pending，不输出负值、不取绝对值、不假设新表从 0 起算 |
| 明确复位 | 计算复位前后各段；多次复位可累加，不能遗漏中间消耗 |
| 明确回绕 | 按声明 modulus 和绑定的精确圈数计算，不能默认只回绕一次 |
| 读数上升但可隐藏整圈回绕 | 没有精确圈数或足够严格物理上限时 pending |
| 窗口缺采、不对齐 | 保留实际前后时间范围及 pending，不均分或虚构中间读数 |
| 单位换算产生非整数规范计数 | pending，保留 rawDelta，不浮点舍入后入库 |
| 规范值超出 numeric(30,0) | pending，不能截断或溢出 |
| 端点 pending/rejected 或映射/epoch 变化 | pending，不回退旧的有效读数 |
| 同修订冲突、跨租户/对象/单位或同刻冲突读数 | 明确拒绝，先由来源/隔离服务解决，不能任意挑选 |

结果携带规则版本 `bsmoss-counter-v1`、能力/策略/映射/转换版本、主体与规范单位、
前后读数引用、转折证据引用和确定性 SHA-256 输入指纹。
同事件重放、输入乱序和等价时间表达不会改变结果指纹；策略、输入修订或质量结论变化会改变指纹。

原始计数、换算因子、模数和圈数使用十进制整数字符串与 bigint 运算。
换算先对差分乘以分子，再除以分母，要求整除；累计端点不分别舍入。
速率上限以精确毫秒交叉相乘核验，不采用浮点百分比容差。
复位证据的每个连续分段也要满足速率及回绕歧义检查；同一时刻不能凭空增加用量。

## 修订、缺口与重算

同事件选最新测量修订，并选该修订的最新质量决定。最新版本被撤销时不会回退旧 verified。
同刻不同事件必须先明确源序列或权威，规则不自行选择“最后接收者”。
转折证据绑定旧修订时，相关区间输出 stale_transition_evidence 并保持 pending。
不再对应相邻读数的转折证据明确拒绝，避免新增读数后悄悄将旧回绕说明套到另一个区间。

中间读数修订会同时改变前后两个候选增量；中间质量撤销也会使两边暂停采用。
后续重算调度必须重新读取必要前驱/后继并更新这两个区间，不能只重算修订读数的“当前窗口”。
本批没有实现重算队列和结果发布；指纹提供后续版本化与幂等处理依据。

无依据下降后的区间保持缺口。之后两次同 epoch 的有效采样可以恢复正常差分，
恢复不补写此前未知消耗，也不会因前一个区间 pending 而将永久连续缺失伪装成零。
15 分钟来源缺采时，两个采样之间即使可求得跨度总差也不被拆成若干 15 分钟事实。
来源只有小时粒度时应按小时能力处理，之后才进入小时或更粗聚合。

## 验证结果

新增 26 项行为测试，总计 224 项单元测试通过，根/app 双层类型检查通过。
覆盖 D03 A08（10000→10300→10500 得到 500Wh）及 A09（无依据下降保持 pending）。
另验证精确/多次复位、整圈/多圈回绕、隐藏回绕、速率边界、定点换算、30 位整数、
端点质量撤销、修订传播、源粒度、跨主体隔离和证据冲突。
使用 20 组确定性递增序列验证差分和等于首末差；移除一个采样时产生明确缺口。

新增一条测试层联通路径：累计规范化候选经过测试专用的质量批准样例，再进入已有周期聚合。
其中有效区间 300+200+50=550Wh，下降缺口不参与汇总，小时结果明确为 partial（3/4 窗口）。
这条用例不是生产自动批准流程，不代表已有连接器落库或正式报告。

本批未修改数据库、依赖、界面或部署；数据库静态镜像仍为 26 表。
