# P6 报告中心与生成流程

日期：2026-11-09。依据：用户确认推进 P6，并要求报告中心能够反复查看所有已存报告和历史版本，生成构成完整流程。

## 页面职责

`/reports` 是报告库；`/reports/new` 是生成工作区。用户查阅报告通常不需要重新选择条件或重新计算，生成只在主动点击后执行。生成过程在同页完成，不再拆分选择、预览和入库页面。Launcher 将报告生成指向新工作区，原 `/usage-reports` 普通预览链接转入此流程；地图选区、旧历史证据和正式模式保留既有路径。

报告库列出当前范围全部已存周期，提供运营商、报告类别、实时／回车检索、重置、列表／卡片、页容量和分页。报告保存时间倒序排列，移动端副标题保留类别、日期和运营商。打开报告显示留存正文、保存时间和版本信息；同一范围多版本可切换，下载 HTML／JSON 原文件，返回列表继续查阅。

生成按区域、运营商、日期、日／周／月选择。输入验证覆盖行政关系、运营商、真实日期和来源日历边界，拒绝夹带明细搜索／分页条件。只有点击生成预览才请求汇总；预览确认后显式入库，进入页面及筛选变化不自动生成。条件变化取消请求并清除旧预览；入库失败保留预览，支持重试和下载。

## 数据与留存

新增 business-usage-report-v1 快照复用 P5 businessUsageModel，使用2024-11-01至2026-10-31已有合成历史。报告包括四项指标、上下行及尝试计数、运营商和区域分布、周期序列、完整站址成员，非当前表格页截断。区县范围仍保留该区县分布，避免空白区域卡片。

流量三项使用精确整数字符串，其余计数为非负安全整数。读取同时验证字节上下行关系、七项原始计数在运营商／区域／序列／站址四个维度的守恒、成员数及外层元数据一致性。快照冻结名称、来源和模板版本。摘要对完整文件内容计算，相同内容重复保存保留原 savedAt；同范围但内容改变保留独立版本，不覆盖。

新模板生成独立完整 HTML 和 JSON。HTML 包含全部站址及原指标，使用已有生成报告的主题 token，文本转义；页面正文直接使用留存 JSON，不调用实时分析或生成。旧 calendar／history 文件保留原格式，正文由空 sandbox 的 iframe 展示，限制脚本和外部请求，下载内容保持原样。

复用 bsmoss-local-report-library-v1，不另建并行本地库；沿用50条、64Mi字符总容量和单文件边界，失败明确提示，不自动清理旧报告。焦点及跨标签通知刷新库列表。此处是显式产品预览的浏览器留存，不能跨设备共享，清理浏览器数据会影响本机报告。正式 OIDC、PostgreSQL归档、任务和发布现有流程未改为演示实现；没有新增服务端假记录、定时任务、大模型或审批。

## 组件与实现

复用 PageHeading、PanelCard、DataTable、ListCard、ViewModeSwitch、Select、SegmentedControl、Pagination，以及 site-analysis 操作行、紧凑统计、成对概况卡片和交互图表。按钮使用官方32px规格；没有新增业务按钮／表格原语或硬编码视觉尺寸。共用样式仅增加历史正文预览容器，以现有media token决定高度。

规则与读取校验在 generation-rules、business-snapshot、local-rules，服务生成在 business-service／business-html，存储仍由 local-store 执行。生成接口 `/api/product-preview/business-report` 仅在显式预览开放，JSON限定、请求体4096字节上限、无缓存，不写入服务端归档或配置。

## 正文完整性修正：恢复原报告价值（2026-11-09）

用户说明原功能所生成的报告内容更丰富。核对原daily／calendar模板与history模板，确认首次P6实现把报告收窄成四项用量和分布表，遗漏环比、运行指标、忙时、重点站址等。此次保留已建设的库和生成流程，报告模板升级bsmoss-business-report-v2，补回内容，不另拆页面或引入大模型。

新增纯规则analysis-rules，复用calendarSource、calendarRates、counterChange、aggregateBusinessUsage、physical累加和既有分类字典，按报告完整站址范围及选定日历计算。日周月的群体忙时、最高小时负载、最低小时接通、运营商运行分项、物理能耗／强度、温度均值／范围、备用供电站址及站时、服务样本、重点站址及单站峰值随快照冻结。日均用观察到的自然天数；比较仅在完整范围和基期覆盖时开放，月间天数不同分别保留总量与日均变化。同比支持已有两年历史，覆盖外显示基期不足，零基期不除零。流量增减以精确有符号字节计算，保留全体正／负合计和各方向前5站，不将前5冒充全量。

按场景、站型、共享各自独立分组，每组站址数和七项计数都守恒。物理能耗每站每小时一次，单运营商未分摊；温度使用十分之一度整数累加，避免浮点累计漂移。业务计数沿用P5精确值。分析扩展读取校验覆盖计数、比例、时间、分组守恒、时段合计、比较元数据，v2缺章节拒绝，v1无扩展继续接受。
