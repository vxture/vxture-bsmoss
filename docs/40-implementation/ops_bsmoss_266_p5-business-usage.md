# P5 业务用量迁移

日期：2026-11-09。用户确认运行能效阶段完成后，批准业务用量规划并要求开始实施。

## 目标与页面

将 `/operator-usage` 主入口迁入通用站址分析工作区，名称统一为“业务用量”，Launcher 纳入经营类。页面回答业务规模、分布位置和站址贡献，保留流量、通话时长、接通次数、短信四项独立指标。覆盖站址跟随统计作为描述，不增加并列指标。运营商名称和标识读取已有可配置目录。

运营商分布展示当前指标总量、占比、站址数与进度；区域比较保留物理站址总数和区域下钻／返回。区域数字采用“万”压缩，Tooltip 保留完整数值、单位和占比。沿用共用网格，在卡片宽度不足时改为单列。一个趋势图切换四项指标，与分布指标同步；不另设趋势页面。

明细提供指标降序、贡献比例、实时与回车搜索、重置、列表／卡片、页容量和连续侧栏。贡献分母是当前地域、运营商和周期的对应业务总量，不受表格搜索影响。侧栏包括运营商分项、上传／下载、呼叫尝试、站址趋势及原始计数。只给当前可见页站址附加序列及运营商证据；翻页后不在当前页的选中站址关闭侧栏，避免展示空序列。该修正落在共用工作区，其余页面同样适用。

## 数据与时间口径

纯规则位于 `domains/business-usage/rules.ts`，视图模型和 UI 分离。复用已有连续合成历史来源 `calendarSource`，覆盖 2024-11-01 至 2026-10-31；没有新造数据源。主页面默认 2026-10-25 日汇总，旧 hour 参数仍映射单小时。

时／日／周／月作用全页：概况、运营商、区域、趋势、排序、明细、贡献及详情使用同一窗口。周一为周起点，月份按实际天数；边界周期只纳入来源覆盖日期，周期描述展示有效天数。越界日期定位最近有效小时，前后周期按钮按真实日历移动，到来源边界禁用。日按小时展示，周月按日；周月直接调用已有 daily 整数公式，避免为全省逐站保留每个小时对象。

业务计数分别汇总，流量 = 上传 + 下载；Bytes 原值保存十进制整数字符串，BigInt 汇总与比较，防止月度全省流量越过安全整数范围。语音保留整数秒，接通／尝试／短信为整数且检查安全范围；展示才换算 GiB 和小时。比例和图表使用展示数值，不回写原始计数。物理站址去重，运营商归属可交叉，不相加冒充物理总数。

不添加业务用量高低阈值、异常判定、接通率或负载分析；不增加大模型、收益或费用推断。历史对比不在本阶段。地图 selection 入口继续走既有选区流程；正式模式保持待接入，不加载合成用量。

## 成对概况卡片与条目对齐（2026-11-09）

根因是外框拉伸等高，而标题和正文各自排版：左侧选择组抬高标题，分布使用Flex间距，区域使用另一套Grid行高和padding，导致同为五行仍逐行错位。修正在共用AnalysisOverview与site-analysis.css内完成，没有添加P5专用补偿样式。

并排卡片使用CSS subgrid共享标题／正文轨道，标题第一行以32px控件高度为下限，分隔线和正文起点同步。响应式容器放在标题包装层，避免卡片自身的布局包含阻止继承网格；容器断点按标题可用内容宽度调整，窄卡片选择组仍在标题内换行。堆叠布局按各自内容自然排版。

分布条目全部使用共用entry结构，图标作为可选列。分布与区域统一8px内边距、8px行间距、最小64px行高，数值和进度条垂直居中；尺寸来自既有语义token。阈值说明较多的条目允许自然增高，不裁切内容。不同业务条目数或窄屏区域列数不强行凑齐。
