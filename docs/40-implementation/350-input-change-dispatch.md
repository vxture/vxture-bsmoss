# I09测量及质量持久变化传播

2026-11-02。内部端到端实现，无真实接入／外部发布／生产上线。

## 实现入口

input-refresh定义受控输出订阅摘要、历史旧／新区间规划与字典反向依赖。pg-input-refresh提供pendingInputChanges有界发现和dispatchInputChange单变化消费；从实际测量修订解析完整历史对象与区间，当前授权全部覆盖后才入队。refresh-enqueue抽出外层事务绑定入口，复用可信快照及现有队列，不接受预计算结果。

空库DDL新增input_change及input_refresh_receipt两表、测量／质量INSERT捕获触发器和固定search_path的受限捕获函数。Prisma同步标量镜像，共35表。变化运行时只读，消费清单追加；未增加依赖或旧库迁移。

一个源变化按配置产生所有相关日／周／月任务；状态保守覆盖最大保持期间的未知抑制，直接接通率不因依赖次数变化而误重算。全部job与消费回执同一事务，聚合执行另由原可靠租约步骤完成。没有全局时间／ID消费游标，晚提交变化不会遗漏。

## 验证

新增5项纯／边界测试，总计400项通过。覆盖scope及配置摘要、排序重放、旧新历史和反向依赖、状态短TTL后的影响、去重及超限、数据库前的授权拒绝。

新增10个真实PostgreSQL子项，总计107项报告测试（106子项＋父项）通过。覆盖捕获原子性／冲突重放／只读运行权限；直接与依赖输出任务及消费重放；修订移对象移日期撤回旧值且保留旧聚合；质量修订重算；job／消费回执故障及授权过期整体回滚；并发try锁及重启重放；晚提交事务在新事件消费后仍可发现；旧新对象全量授权与订阅隔离；状态失效后的未知影响；直接比率策略与依赖权威缺失拒绝。

旧missing-quality测试是owner故意删质量的损坏夹具，新外键禁止删除仍被变化引用的证据，因此夹具先由owner删对应质量变化，再删质量。运行角色权限保持只读／追加；未为通过测试放宽约束。另一失败来自夹具选择了已消费的同事件另一分量，改用独立事件后复验通过。

类型检查、Prisma校验通过；最终生产构建／HTTP／守卫／ASCII及密钥扫描、Git提交与运行SHA以检查点和agent收尾记录为准。无UI变化，不重复六场景浏览器。专用PG只创建／删除随机合同库，不操作业务数据库。
