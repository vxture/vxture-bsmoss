# 塔服研判：T01–T08迁移实施计划

日期：2026-11-10。依据[页面级PRD120](../20-specs/120-tower-service-page-prd.md)。本文件是当前实施批次与迁移状态权威。

## 1. 编号与当前状态

新方案固定**8批，T01–T08**。T表示塔服研判本轮迁移，不延续历史P1–P18，不将旧五阶段计划的已完成工作重新编号冒充新批次完成。

当前**T01–T08本地验收完成（8/8），本轮八批结束**。[T08验收291](../40-implementation/ops_bsmoss_291_t08-navigation-acceptance.md)完成六前台、两后台主入口切换和13+6视图整链路回归；原功能收入次级“原有功能（待迁移）”，45条旧页面路由、快照、配置和报告历史保留。新品牌入口进入经营总览，根路径仍保留原运行总览。正式来源、客户服务、月度租户／锚定、客户表计及协议、生产存储和组织授权仍待接入／确认；本地验收不代表投产，不新增T09。

旧[五阶段计划60](60-site-service-batches.md)转为历史：阶段1内部口径、阶段2资源快照、阶段3整站观测／计量的本地成果保留；原阶段4／5未实施，其后续排期由本计划替代。旧“服务履行／故障／维护／SLA”方向不再扩建，符合新范围的代码与证据可复用，不能沿用旧目标继续开发。

## 3. 各批任务清单

### T01：迁移基线与统一查询

- T01.1 固定现有页面、兼容路径、历史报告和记录的迁移清单，记录原名称、语义、权限及目标。
- T01.2 将“待迁移”“保留旧版”“部分迁移”“已迁移”“待接入”“待确认”区分；已有入口逐项标记，新目标未就绪不伪装可用。
- T01.3 确定目标路由及兼容清单；需要接管原路由时，先给旧内容稳定可达入口并验证深链接。主导航最终切换在T08，不预先批量重定向。2026-11-10用户追加授权在T05先整理Launcher：已可用新入口置上，原有功能集中置下并标待迁移，名称和路径保留；这部分入口整理提前，不代表T08全链路验收已完成。
- T01.4 统一snapshotId／businessPeriod／operatorScope／regionScope及A/B上下文；复用页头和通用样式，保留业务／存量／同步三个时间语义。
- T01.5 用一个可用切片验证全局筛选、URL及前后退、跨页携带与权限；旧页尚未支持新快照时明确旧版上下文，不注入新参数后假称全页联动。

不在T01一次性创建19张空页面或重写全部业务。交付以迁移标识及一个真实可用切片为准，既有合成数据仍标演示，不能宣称真实来源接通。

### T02：快照同步与规则底座

- T02.1 对照已有接收／调度／校验与存储审计能力建立能力缺口清单，不因现有任务页存在就认定生产定时拉取已经完成。
- T02.2 实现同步计划、快照版本、日志校验三个视图及对应授权动作；触发来源、范围、业务期间、幂等及失败重试统一。
- T02.3 构建快照来源清单、版本／修订、完整性、原子发布及旧版保留，业务截止不采用同步时间冒充。
- T02.4 建立客户／服务／单位字典、协议和规则版本框架，以及总部／省／市×客户范围×操作权限；广电和其他默认待确认。
- T02.5 验证一个来源从接收、校验到固定版本查询的闭环；适配器未有正式授权／样本时使用明确隔离的本地数据，不新增生产凭据或网络拉取承诺。

真实来源、来源授权、协议字段及平台身份接通单列依赖。需要持久化变更时按仓库DDL及受审db-init约束执行，不在应用启动时建表，不以逻辑模型草案冒充已落库。

### T03：资源底数迁移

- T03.1 迁移站址及铁塔设施，区分客户自有设备；保留既有单站资源详情。
- T03.2 建立逐月站址—客户租户快照及锚定三态，区分品牌和具体客户、有效期未知和明确有效。
- T03.3 实现三页签、省市对比及未归属分组；客户筛选显示关联站址内物理设施，不伪称客户独占资源。
- T03.4 核对共享分母、客户去重、资源去重、可见租户集合与权限；快照对比不自动认定实际交付／退租。

无真实月度租户／锚定来源时显示待接入或待确认，不用当前品牌关联补造历史。物理资源可用并不代表客户服务配置已确认。

### T04：服务量化迁移

- T04.1 将客户、具体服务、配置、期间和单位显式关联；原station_service及通信service_id不重新解释为新服务项目。
- T04.2 实现运营商比较、服务构成和期间序列，继承全局版本及A/B可比性规则。
- T04.3 数量按挂载、空间、室分、传输、电力等已确认目录与单位展示；目录未确认不制造总服务量。
- T04.4 校验物理底数、客户配置量及计量用量的边界；无有效期不得据台账日期编造周期服务规模，无历史数据不得补成完整趋势。

通信流量、通话、短信原功能继续旧版保留；只有实际协议／服务关联明确时才可作辅助依据，不直接迁成铁塔服务量。

### T05：计量依据与口径追溯

- T05.1 迁移整站可靠区间量和原始记录；引入表计、客户归属及有效绑定，明确实测／协议分摊／估算／待归属。
- T05.2 实现依据汇总、明细和口径对照，所有统计固定同一数据版本及适用规则集。
- T05.3 将每项依据连接到来源、单位、边界、协议、口径、适用月份租户／锚定及共享档位。
- T05.4 校验总分表去重、换表／复位／倍率、归属跨期、分摊守恒及规则冲突；没有分段数据不按时间比例擅拆用量。
- T05.5 后台只对非金额数量和档位应用规则；价格默认保存条件引用，单价原值是否存储等待业务确认，禁止实现价格×用量或折后金额。

此批承接旧阶段4中符合新边界的依据目标，但不是旧阶段4继续执行；不迁入故障／SLA／维护和费用确认流程。

### T06：分析研判与历史报告

- T06.1 配置并应用资源／服务／计量变化、依据缺失冲突、租户锚定及规则不明确事项；缺来源不生成全量异常。
- T06.2 展示规则版本、基准、实际值、阈值、涉及范围、依据及简短建议，不创建工单状态或审批流。
- T06.3 报告统一在分析研判中生成、查看、导出；保存全部数据／规则／模板版本清单，重新生成创建新报告。
- T06.4 旧报告、生成任务、归档证据及用量核验历史保持原标识及语义，可按原入口阅读；新历史列表可链接旧报告，但不得在新权限下泄露旧合计。

不预设大模型接入；已有智能化或趋势页保留旧版，后续大模型需求另行确认，不形成额外T批次。

### T07：经营总览与站网全景

- T07.1 总览以已验收资源、服务及事项读模型为唯一统计来源，控制概况数量，不再实现一套独立聚合。
- T07.2 区域色块／聚合热力支持资源、服务、共享率和A/B差异；单位、图例、未归属及未知分开。
- T07.3 全省→市、总部→省及县级预留一致；点地图跳同版专题，专题返回保持上下文。
- T07.4 原点位地图及其旧工具继续保留旧入口，新区域地图不复制实时监控、故障跳点或独立设备分析。

### T08：主入口整合与整体验收

- T08.1 主Launcher及后台导航归并为六前台、两后台；旧版通过次级“原有功能（待迁移）”集合可达，不作为第七个前台业务板块。
- T08.2 对已验收迁移项更新状态；无替代或新范围之外的旧功能仍标“保留旧版／待迁移”，不为追求全部迁移而重造超范围功能。
- T08.3 回归13个前台及6个后台视图、省市汇总、客户权限、任意A/B、月度租户、协议追溯、报告历史和导出；适用环境运行构建、类型、规则／边界测试和主题／窄屏检查。
- T08.4 输出最终迁移矩阵、已接／待接来源及待确认口径清单；清点深链接、原报告及历史记录，验证导航可回退，不删除旧代码、路由、数据或规则。

T08后本轮八批结束。未接来源和未确认协议保持明确状态，不宣称业务投产；真实接口联调、生产授权、容量、部署及UAT按已有上线依赖另验收，不能用本地演示替代。

## 5. 保留及标记规则

| 状态 | 使用条件 | 用户看到的含义 |
|---|---|---|
| 待迁移 | 新目标明确、尚未替换 | 原功能可使用，仍是旧口径 |
| 部分迁移 | 已验收部分内容移入新页，原页还有不同语义内容 | 清晰列出迁到哪里及尚保留什么，不将整页标完成 |
| 已迁移 | 对应能力按新PRD验收 | 新入口为主，原URL及历史仍可达 |
| 保留旧版 | 新范围不包含或尚无等价替代 | 暂不扩建，不强行塞入新分析 |
| 待接入 | 真实来源／适配／授权尚缺 | 不当作零或已确认，不生成全量问题 |
| 待确认 | 业务定义／协议规则未签认 | 仍可展示原始事实，相关计算不启用 |

迁移状态与数据接入状态是两个维度，例如“页面已迁移，客户分表待接入”。部分能力验收不改变原证据；旧链接若需要转向必须到同语义内容并保留版本、范围及权限，无法保证时保留原页。原数据不重编号、不覆盖、不删历史、不自动把旧核验转成新事项。

删除不属于T01–T08。后续确需删除另列具体对象、替代和恢复依据，获得单独授权；不得因代码看似闲置或新入口已切换而自动删除。原规划禁用功能继续保留记录，不占新主导航，不创建新空页面。
