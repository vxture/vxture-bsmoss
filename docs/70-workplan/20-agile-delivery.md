# 敏捷交付与阶段推进 V1.0

基线日期：2026-10-28。范围：三类数据的周期性分析、可配置展示；费用仅预留。
本计划替代“按完整领域逐层完成后才展示”的推进方式，以可演示、可测试的纵向切片交付。

## 交付节奏

建议每迭代 2 周；首轮为工作量安排，不是已承诺的完成日期。团队人数、真实来源和环境
尚未确认，以下迭代序列用于排序，完成首轮后依据吞吐量重新预测，不直接换算上线日期。
复杂任务拆到 1–3 个工作日可检查的子任务；估算超出 5 点时先拆分。

每轮：计划与目标 → 补充设计 → 实现与自动检查 → 集成部署 → 演示验收 → 回顾与重排。
每天更新任务状态、阻塞及下一步；每轮至少交付一条可验证业务路径。
技术债、缺陷、部署工作进入同一待办，不视为迭代之外的隐形工作。

## 看板与责任

状态：backlog → ready → in_progress → review → verified → done；blocked 单列原因、依赖人和解除条件。
文档存在不代表业务功能 done，部署成功不代表已上线验收。每张任务卡只有一个当前状态。
工作在制限制：每位实施者最多一项 in_progress，优先处理评审和阻塞。

角色：产品负责人裁定范围与业务验收；技术负责人负责架构、契约及设计评审；
实施负责人负责代码与验证；发布负责人执行部署/恢复；业务代表完成真实来源口径核验。
当前角色尚未指定人员，计划不虚构已有人负责；单人可兼任角色，关键验收仍需留下依据。

## 六个交付阶段

| 阶段 | 建议迭代 | 目标增量 | 出口证据 |
|---|---|---|---|
| G0 设计基线 | S0 | 三类指标、来源假设、关键实体、配置契约和验收样例 | 设计记录与样例；待确认项显式登记 |
| G1 可运行骨架 | S1 | 三类最小指标字典、配置校验、可信身份适配、首个纵向界面 | 自动检查和本地演示；测试数据明确标识 |
| G2 真实接入闭环 | S2 | 首个真实来源、持久化、质量、幂等、证据到周期汇总 | 真实来源核验、DB 契约测试与集成部署 |
| G3 周期分析 Beta | S3 | 三类面板、配置、日报/周报/月报、修订和导出 | Beta 演示、角色隔离、试点报告比对 |
| G4 试点与上线准备 | S4 | 异常核验、负载、安全、恢复、运行手册与回滚演练 | UAT、容量报告、故障演练、发布清单 |
| G5 生产上线与扩围 | S5 起 | 小范围生产验证、稳定观察、分批接入 | 生产检查与业务验收、观察记录、扩围决定 |

S0 可以立即推进不依赖外部资料的字典与模型设计；真实来源未就绪时使用标记清晰的
样例验证技术路径，不把样例完成作为 G2 出口。不是所有候选指标都必须接入后才能上线。
若短信等指标无来源，可明确延期；三类各至少一个真实可核验指标是首发目标，
若只能支持部分类型，需正式缩小首发清单并更新验收，不能标记全部已支持。

## Definition of Ready（可开始）

任务有稳定编号、用户价值/交付物、范围与排除项、可验证验收标准、依赖及估算。
真实来源任务需样例与授权，设计/纯规则任务可基于明确假设先行。
跨领域写入、指标公式、数据范围、DDL 变更先有对应设计；不要求一次设计完全部领域。

## Definition of Done（完成）

代码与设计一致，适用的类型、规则、权限和真实数据库检查通过；涉及页面有状态与操作验证；
涉及迁移有新库/升级演练；异常、缺数、零值和未接入可区分；文档与任务状态更新。
在评审记录中关联变更与验证结果，所需 CI 通过后才合并；当前未建立远端 PR/CI，不能声称已通过远端门禁。
集成部署及业务验收作为对应发布卡单独完成，不让单个纯规则任务承担完整上线条件。

## 版本与范围控制

设计和任务使用 V1 基线；产品版本可采用 0.1.x 内部验证、0.2.x Beta、1.0.0 首发，
最终发布号在可发布构建产生后确定。需求变更先更新指标目录与任务，记录影响和替换项。
费用、实时控制、无人机及机器狗均不进入本阶段迭代。

部署与上线见 [发布推进](../50-deployment/20-release-plan.md)。
