# 阶段1：站址服务目录与数据口径基线

日期：2026-11-10。承接[产品定位](100-site-service-analysis.md)，交付服务目录、最小字段、来源盘点和汇总规则。全省、市级为主要分析及报告交付视角，县级预留，单站服务为明细与证据层。

本阶段完成的是仓库核对及内部数据口径，不是客户合同签认、真实来源接入或新页面交付。下列字段为后续读模型的业务约定，不是新增数据库表或接口；DDL仍为唯一持久化结构权威。本阶段不修改现有业务数据、旧分析、报告及核验记录。

## 1. 服务目录

五类用于分析归类，不预设每站都具有五项，不将配套服务重复拆成收费项目。具体项目和组合以订单及交付材料为准。

| 代码 | 服务类别 | 最小交付事实 | 可比较数量／单位 | 必须关联的依据 | 不能替代该事实的数据 |
|---|---|---|---|---|---|
| mounting | 塔桅挂载 | 某客户在某站实际交付的挂载位置及配置 | 挂载位置／个；挂高／m独立展示 | 订单项目、交付确认、配置及变更 | 站内天线数量、塔体高度、通信负载率 |
| space | 安装空间 | 某客户取得的机房、机柜或其他安装空间 | 机柜／个、机位／个或面积／平方米，按资源子类分别汇总 | 使用位置、配置规格、交付及增减确认 | 站内设备数、机房总面积 |
| facilities | 配套设施 | 为服务项目提供的配电、空调、接地等约定配置 | 按同一设施子类及可比规格统计；能力值单列 | 配套清单、服务归属、验收及有效期 | 共用设施与所有入驻客户的自动关联 |
| power | 供电及保障 | 某服务约定的供电接入、容量、备电及应急保障范围 | 接入点／个；约定容量按同口径kW或kVA分别展示；计量电量按Wh | 交付配置、供电约定、计量关系、保障与事件记录 | 总表电量均摊、蓄电池状态直接认定供电违约 |
| maintenance | 维护及约定服务 | 明确服务对象、维护范围和约定要求 | 有效服务对象；履行阶段按已确认工单／次及持续时间统计 | 合同／订单范围、工单、处理及结果确认 | 别名、位置备注等台账编辑记录 |

一个订单项目可同时涵盖多类服务；允许同一服务项目的多个配置分项分别归类，但服务项目数只计一次，不能因五类配置产生五份订单。服务内容是否单独收费不是分类条件。

物理设施所有权、实际使用者和服务提供方分别记录。运营商无线设备可以证明安装或使用线索，不能默认认定为铁塔交付资产。

## 2. 最小关联模型

以已有站址和客户实体为基础，补齐以下业务关联，不为每个对象新建管理页面：

1. **客户与站址关联**：说明谁在站内；复用旧station_service的关联身份，不将其直接视为服务项目。
2. **服务项目**：说明向具体客户交付什么；一个站址客户关联可有多个服务项目，关联合同／订单的具体项目及版本。
3. **配置版本及分项**：说明具体位置、资源、规格、数量和有效期；同一项目可以关联多项资源，共用资源可被多个项目引用。
4. **期间证据**：交付、变更、终止、计量和履行记录引用上述对象及其版本；一份证据可支持多个对象，但不能重复生成服务数量。

省、市、县通过站址归属关联，不在客户名称或订单号中解析地域。来源身份使用“工作区＋来源＋对象类型＋外部标识”，通过显式映射得到内部标识，不能按名称、Logo或编码前缀猜测。

旧station_service.service_id与未来服务项目serviceItemId保持不同语义。已有通信用量的service_id引用关系、权限范围及历史证据不重命名、不重新解释；后续增加对应关系时必须显式保留两种标识。

## 3. 最小字段字典

“必需”表示该记录进入对应分析前应具备，并非要求来源一次提供全部。字段未知可以保留来源事实及缺口，不能补造默认值后计入已确认统计。

### 3.1 身份、地域与查询范围

| 字段 | 业务含义与规则 | 阶段2使用 |
|---|---|---|
| workspaceId | 可信会话及来源绑定确定，不接受浏览器声明的归属 | 必需 |
| siteId、siteCode、siteName | 稳定物理站址标识；编码／名称只做展示与映射依据 | siteId必需 |
| provinceCode、cityCode、countyCode | 站址行政归属；省、市主交付，县可空且预留 | 省、市应解析；县未知不影响市级合法事实 |
| regionVersion、regionBasisAt | 归属映射版本及基准时点，快照内保持一致 | 汇总必需 |
| providerEntityId、customerEntityId | 实际提供方与客户实体；品牌分类另记operatorCategory | 已确认客户服务必需 |
| relationId | 旧站址与客户关联的可选引用，不代替serviceItemId | 复用时保留 |
| periodStart、periodEnd、asOf | 期间流量事实与存量时点分开；共同使用Asia/Shanghai | 查询必需 |

铁塔在本业务中为提供方，客户数量不包含仅有提供方角色的铁塔。一个实体在其他业务有客户角色时须有明确项目依据，不由品牌分类自动推断。other只用于品牌分类，多个其他客户必须有不同customerEntityId。主体配置中新增Logo／简称不会自动新增有效服务客户。

### 3.2 服务项目与配置

| 字段 | 业务含义与规则 | 必需条件 |
|---|---|---|
| serviceItemId、serviceItemVersion | 项目稳定身份及来源修订；同项目多版本不重复计数 | 服务项目统计 |
| contractRef、orderRef、orderLineRef、agreementVersion | 来源合同／订单／项目引用及版本；不要求同时具备三类编号，按适用凭据关联 | 费用依据核查；没有合同引用不抹去已观测资源事实 |
| serviceCategory、resourceSubtype | 五类服务及可比较子类；不能仅凭设备类别自动映射 | 分类配置统计 |
| configurationId、configurationVersion | 一组交付配置及版本 | 配置追溯 |
| componentId、resourceId、positionRef | 配置分项身份、物理资源／位置引用 | 数量去重；物理资源无法对应时标待映射 |
| quantity、unit、specification | 精确数量、单位、规格；固定精度数或整数字符串，不用浮点累计 | 数量汇总；数量未知仍可展示服务条目 |
| validFrom、validTo、validityBasis | 实际服务有效期及其依据；起租确认、交付确认按来源分别保留 | 时点与期间有效性判断 |
| observedAt、confirmedAt | 观测及确认时刻，与服务生效时间分开 | 快照／确认记录 |
| changeId、changeType、effectiveAt、beforeVersion、afterVersion | 新增、配置变更、终止事件及生效时点；必须有版本前后链路或明确初次交付／终止依据 | 期间变化统计 |

来源明确“持续有效、无约定终止日”时validTo可以空，并以validityBasis标明；不清楚结束日期与确认无终止日不是同一状态。validFrom未知的快照只进入“已观测、有效期待确认”，不能当作从系统建库日开始服务。订单日期、资产投运日期不能替代实际交付或起租日期。

### 3.3 计量、履行与共同证据

| 对象 | 最小字段 | 用途与边界 |
|---|---|---|
| 表计与计量归属 | meterId、measurementPointId、meterRole、siteId、customerEntityId／serviceItemId（适用时）、bindingVersion、validFrom／To | 区分站址总表、客户分表、公共用电及其他表；归属必须有有效期间 |
| 读数与电量 | readingId、readAt、readingValue、unit、multiplier、quality、reset／replacementRef；或明确来源的intervalStart／End、deltaValue | 累计读数先处理倍率、换表和复位；可靠区间电量可直接接收，不伪造起止读数 |
| 分摊 | allocationRuleRef、ruleVersion、periodStart／End、inputRefs、targetRefs、allocatedValues、unallocatedValue、calculationBasis | 独立计量、按约分摊、估算分开；结果与输入守恒；同一能量不累计总表再累计分表 |
| 履行事件／工单 | eventId／workOrderId、eventType、actualStart、actualEnd、recordedAt、affectedSiteIds、affectedServiceItemIds、impactBasis、confirmation | 区分市电停电、客户供电中断、设施故障、维护和恢复；观测时间不能自动等同受影响期间 |
| 合同服务条件 | conditionRef、agreementVersion、serviceScope、effectiveInterval、conditionValue／unit、evidenceRef | 与监测参数分开；只供对照，不启用费率计算及扣费 |
| 共同来源 | sourceId、externalId、sourceRevision、receivedAt、mappingVersion、evidenceRef、digest（可获得时）、dataMode | 原件或源记录可追溯；demo／production分离，修订不覆盖旧证据 |

服务事实确认、测量数据质量、来源接入状态使用不同字段，不合成一个“已验证”标签。measurement.quality=verified仅说明对应测量通过质量判断，不表示合同、客户确认或履约认定已经完成。

## 5. 省市汇总及县级预留

### 5.1 统一范围

同一分析结果固定工作区、授权站址集合、行政归属版本、客户范围、服务类别、期间、存量时点和来源修订集。全省及各市概况、下钻明细和报告共享这些条件；明细分页、搜索和局部排序不改变整体统计。

省级总览展示整体与城市比较；市级展示本市结构、变化、事项及涉及站址。县级标识进入数据契约，但本阶段不新增县级专页或地图专题。单站服务层提供资源、配置、生效期及证据，不以逐站录入作为主要交付流程。

行政区采用统一asOf归属快照：同一站址在同一结果中只归一个市、一个县。历史归属未掌握时标记“按当前归属”，不伪造历史辖区变迁。市已知、县未知的记录仍进入本市并置于县级未归属；市未知的合法省内记录归省级“市级未归属”。无法确认省份的事实不硬塞进陕西总量，单列待映射。

已授权范围的省合计必须能够与各市及市级未归属核对；市合计与各县及县级未归属核对。不同授权用户的总量可能不同，汇总不能先取全省数再只遮挡明细。

### 5.2 核心统计定义

| 指标 | 统一口径 | 省市核对方式 |
|---|---|---|
| 在服站址数 | asOf时点至少一项已确认有效服务的siteId去重；快照入驻站址另列，不能混作已确认在服 | 唯一市归属下，市及未归属站址数可相加为省数；客户分项有交叉，不直接相加 |
| 服务客户数 | 当前范围有效服务的customerEntityId去重，品牌分类另作维度 | 省级重新去重，不能相加各市客户数 |
| 有效服务项目数 | asOf有效的serviceItemId去重，配置多版本不重计；跨站订单须有站址项目分项 | 同一站址项目唯一归市可相加；跨站订单数不作为项目数 |
| 客户站址数 | siteId＋customerEntityId去重，仅作服务规模与结构说明 | 同客户跨市按站址累加；多个服务项目不增加客户站址数 |
| 同类配置数量 | 对有效配置分项按category＋subtype＋unit及可比specification汇总quantity；共有物理设施数量另按resourceId去重 | 分项唯一归市可加；客户使用配置和共有物理数量不能混为同一指标 |
| 本期新增／终止项目 | effectiveAt落在[start,end)的有依据changeId／项目事件，按类型分别去重 | 市可按同一asOf归属核对；不由流量从零变为非零推断新增 |
| 本期配置变更项目 | 本期存在有效配置变更的serviceItemId去重；变更事件次数另外计 | 不强求“期初＋新增－终止＝期末”恒成立，存在修订／补录须列差异原因 |
| 本期有效服务对象 | 服务有效区间与分析期间有交集的项目／客户／站址，按各自身份去重 | 这是期间口径，与期末在服数分别显示 |
| 履行事项及影响 | 已确认事件数按eventId去重；受影响站址／项目分别去重，持续时间按目标对象合并重叠区间并裁剪到有效期及分析期间 | 共享事件跨市时省级事件数重新去重；影响站时不等于事件时长，不能直接累加重叠事件 |
| 本期电量 | 同一计量边界、单位、质量、版本及不重叠时间区间的Wh总量；分表归属及分摊另外标明 | 物理总量只计一次；客户分项在无重叠及同边界时与未分摊量核对；不叠加上下级表 |
| 依据核查事项 | 对应检查具备适用数据清单后，按事项标识去重；涉及站址／项目单独去重 | 同一问题的多份附件不新增事项；来源未接入不生成全量“缺失案件” |

五类服务可能属于同一项目，不相加类别项目数冒充项目合计。数量及电量内部精确计算，展示时换算和取舍，不能将市级显示的四舍五入值相加作为省级原值。

共享率如保留，定义为同一时点有效服务中“至少两个不同客户实体的站址／至少一个客户实体的站址”；当前演示按品牌分类计算的入驻共享率继续保留原名和原口径，不能无提示替换为此新指标。所有比例在省级重算分子分母，不平均市级百分比。

### 5.3 时间、版本与未知值

- 所有期间采用[start,end)，时间戳带时区；同一生效边界旧版本结束、新版本开始，不重复计量。
- 存量以明确asOf时点判定validFrom≤asOf且asOf<validTo；月末统计可指定月末时点，不能把下月零点生效的项目计入上月。期间变化按生效时间，不按同步或补录时间。
- 不同配置版本在期间有变化时分段展示；存量数量不跨小时／天相加。需要服务时长时合并有效区间，不能擅自换算为计费天数。
- 只有快照时显示快照时点与来源，期间、变化显示“依据不足／待接入”；观察到设备不等于服务有效。
- 未接入、未映射、待确认、冲突、可靠零值、无权限分别表达。零只在范围及来源明确时使用；不能把待确认项目放入正常、履约或计量分母。
- 同一来源身份及修订重复接收幂等，冲突记录隔离；新修订保留旧引用。页面与新报告固定同一版本集，已归档报告不被新配置或补录改写。

## 6. 阶段1验收样例

以下仅为设计验收案例，不是正式客户或演示事实，也未向现有系统写入记录。

| 场景 | 后续实现必须满足的结果 |
|---|---|
| 同站同客户交付挂载与空间，分属两个项目 | 在服站址1、客户1、客户站址1、项目2；数量按挂载及空间分别统计 |
| 同一客户在两市各有一站有效服务 | 省站址2、项目按实际分别统计；省客户1，各市客户均1，不能省客户显示2 |
| 一份订单包含两个城市的站址项目 | 订单引用相同，站址项目各自明确；省订单数不能由市订单数相加；项目数量可核对 |
| 同一空调被两个客户服务项目共同引用 | 共用设施物理数量1；不能以两个服务关联生成两台空调或重复计物理用电 |
| 配置在本期中途由2个位置变为3个 | 期末数量3；本期有1个变更项目；配置分段保留，不把2＋3计为5个期末位置 |
| 服务在查询end时刻开始 | 本期新增及本期有效对象不包含该项目，下期包含；asOf另按显式时点判断 |
| 市明确、县为空 | 纳入该市及县级未归属，省市总量不丢；不编造县编码 |
| 总表1000Wh，两个分表400Wh和500Wh | 物理总量1000Wh，不计1900Wh；仅在同边界无重叠时列100Wh未分配／公共等待解释量，不自动认定损耗或向客户分摊 |
| 未接客户分表，整站存在可靠电量 | 显示整站电量；客户电量显示未具备归属依据，不按客户数或通信流量推算 |
| 同一确认中断事件影响同站两项服务 | 事件1、站址1、受影响项目2；不同项目分别计时，站址重叠影响时段取并集 |
| 流量零但交付配置有效、没有终止确认 | 保留有效服务，流量零仅是核查线索，不判定退租、无服务或不收费 |
| 原始测量质量verified，但客户归属或有效期缺失 | 原始计量质量保留；不能据此认定客户已确认、履约正常或费用可结算 |
