# 站址服务与费用依据分析 V1.0

目标设计更新（2026-11-10）：最新[塔服研判页面级PRD120](120-tower-service-page-prd.md)按快照分析、六前台与两后台重新定义目标。本文涉及服务中断、维护、履约／SLA及三内容工作区的冲突目标以120为准；本文仍保留此前决策与实现背景，不代表新PRD已实施。

日期：2026-11-10。根据用户本轮确认，产品主线收敛为中国铁塔围绕站址向运营商提供的基础设施及配套服务，分析实际交付、期间履约及后续费用确认所需依据。本站不执行结算。

本文件是当前业务定位与后续迁移范围权威，覆盖早期规格中“只分析通信用量”和以运行／运营／经营三类指标作为产品主线的要求。旧指标规则、页面、配置、历史报告及核验记录保留；本次不改写其历史含义，不将其升级为合同或结算依据。以下目标内容并不表示已经实现或接入。

## 1. 分析主线

以“站址 → 客户实体 → 服务项目及资源配置 → 生效期间 → 履行与计量证据”为主线。

基础服务事实至少关联工作区、站址、具体客户实体、服务项目／订单标识、配置版本及有效区间。一个客户在一个站址可能有多个服务项目；入驻关系数不等于订单数、收费项目数或费用明细数。铁塔是本业务的服务提供方，不能仅因主体字典包含铁塔就将其计入客户入驻家数。other仅为分类，不代替具体客户实体。

共享率、入驻家数用于说明服务结构；服务关系作为关联基础，不独立扩展成分析重点。

## 2. 三部分分析内容

| 内容 | 用户需要回答的问题 | 主要分析 | 依据与限制 |
|---|---|---|---|
| 服务资源 | 向谁提供了什么、本期有哪些变化 | 塔桅挂载、机房／机柜等空间、配套及供电配置；客户与站址分布；本期新增、变更、终止 | 配置、订单、验收及起止确认；设备台账不直接等于客户使用或计费配置 |
| 服务履行 | 约定的服务在本期是否提供 | 已确认服务中断及受影响对象、时长；供电及保障记录；维护与恢复；与约定条件的差异 | 事件、工单、保障及确认记录与有效服务范围关联；规则告警不直接认定违约，停电不直接认定客户供电中断 |
| 费用依据 | 哪些事实支持费用确认、哪里需要核查 | 服务及配置与合同／订单是否对应、生效期间是否一致、计量与分摊是否可追溯、是否存在需确认的变更或调整事项 | 只整理、比对及输出疑点与证据；不计算应收应付、不出账、不自动扣减或审批 |

供电计量是服务履行与费用依据之间的共同证据，不再另建与两者重复的业务板块。优先查看站址总表、客户分表、公共用电、计量期间和归属关系；独立计量、按约分摊及估算分别标识。没有分表或规则，不按入驻家数、流量或占比推算客户用电。

本期新增、终止和配置变化只有有效期证据齐备时才能统计；当前固定快照不能推断历史变化。资源数量按服务项目的原始单位展示，挂载、机柜、面积、容量及电量不能混加。关注项按明确事项列出，不设计跨服务综合评分。

## 3. 服务内容与观察对象

| 服务内容 | 应观察的交付事实 | 期间证据 |
|---|---|---|
| 塔桅及挂载 | 实际位置、挂高、挂载配置及约定承载条件 | 交付、增减、拆除及确认记录；与通信负载率区分 |
| 机房及安装空间 | 客户使用的机房、机柜、设备安装位置及数量 | 交付、占用配置及生效变更；不能把站内全部设备都算作铁塔向客户出租的资源 |
| 配套设施 | 服务项目约定的配电、空调、接地等设施条件 | 配置、验收、维护与异常记录 |
| 电力供应及保障 | 约定供电条件、计量关系、备电与应急保障配置 | 电表读数、停复电、备电、发电及受影响服务记录 |
| 维护及约定服务 | 约定服务范围、履行对象与要求 | 工单、到场、处理、恢复及结果确认 |

具体适用项目、计价条件、共享规则和履约调整以客户实际合同及确认材料为准，不把通用示例或可配置监测阈值当作正式合同条款。

## 4. 页面与交互目标

交付视角补充（2026-11-10）：全省与市级为主要分析及汇总报告层级，县级预留行政归属、映射及汇总口径，当前不单建县级页面。单站服务是明细和证据层，不以逐站操作代替省市分析。省市与明细使用同一范围、周期及来源版本；客户、项目、站址分别去重，数量按单位分组。完整定义及现有字段缺口见[阶段1基线](110-site-service-data-baseline.md)。

分析采用同一工作区内的服务资源、服务履行、费用依据三个二级板块；当前仅确定内容结构，不立即创建三个独立页面。保留统一地域、客户及分析周期，站址清单与单站详情串联证据；只有数据具备客户归属时，客户筛选才作用于对应指标。

从摘要或疑点进入同一范围的站址／客户明细，再展开具体服务项目及证据。单站详情按上述业务顺序组织，不为每种设施再造分析页面。地图承担空间定位，报告中心承担结果留存，数据更新承担来源与处理，配置管理承担主体、服务目录、映射与规则。

需要概要时，只展示有依据的服务规模、期间变化、履约事项及待核查依据；不固定堆满统计卡片，不因某类数据未接入而制造零值。明细中区分缺少依据、存在冲突、待确认和已确认。只有完整适用清单时才计算完整率；来源未接入不直接制造全量待办。

“待迁移”表示原功能可继续访问，尚未按站址服务口径重构；与“待建设”（无已实现功能）和“待接入”（缺少正式来源）分别表达。待迁移保留原名称、路由、权限、配置、数据及历史内容。

## 6. 当前数据能力与缺口

当前代码具备演示站址／设备／运营商关联、供电与环境等观测、通信业务量及原核验能力。设备维护记录不等于完整履约工单；电表类别不等于具备可靠表计读数及客户分表链路。上述演示不证明正式来源已接入。

尚需确认并接入的关键依据为：

1. 客户实体、服务项目及合同／订单的可靠关联。
2. 挂载、安装空间、配套及供电的实际服务配置与版本。
3. 验收、起租、增减、退租及其有效区间。
4. 表计档案、计量点与客户归属、原始读数、换表及约定分摊规则。
5. 服务中断、保障、维护工单、恢复与双方确认。
6. 合同中适用的服务条件、计量口径及调整约定的版本与证据引用。

以上未具备前，不输出履约合格率、客户应承担电量、费用影响金额或可结算结论。既有监测阈值仅用于调查关注，不能自动变成合同扣费条件。

## 7. 后续实施顺序

本轮完成范围为定位、迁移清单与入口标记。目标服务工作区、来源对接及费用依据核查尚未实施；不启用原预留结算模块，不新增账单、费率试算、审批或收付款流程。
