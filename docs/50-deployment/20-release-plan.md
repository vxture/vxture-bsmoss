# 部署、上线与扩围计划

2026-11-02状态核对：本地门户、生产构建、身份适配、CI与受保护交付配置已实现；正式worker／调度、远端门禁运行、实际环境注册与Beta／生产部署尚未完成。本文件描述后续推进与验收条件，不把本地预览视为上线。
遵守平台和 yucer 的治理约定，具体端口、注册项与门禁集合从权威配置核验，不自行复制分配。

## 环境与发布序列

| 层级 | 用途 | 数据与条件 |
|---|---|---|
| local/test | 规则、DB 契约与开发演示 | 脱敏样例/隔离测试库，禁止冒充真实运行数据 |
| integration/Beta | 集成、回归、UAT 与部署演练 | 可先共用独立非生产环境，账号、密钥和存储与生产隔离 |
| production pilot | 小范围正式试点 | 已授权真实来源与用户，明确首发区域、主体、指标及采样范围 |
| production expansion | 按批次扩围 | 每批核验覆盖、质量、积压、错误与容量，再决定下一批 |

部署是交付构建到环境；上线是将经过验证的能力开放给目标用户；扩围是扩大数据及用户范围。
代码合并不自动等于上线。先单来源/有限区域与样本站址，不以“11 万”作为首日全量接入指令。

## 单次部署步骤

1. 核对构建摘要、目标环境、首发范围、配置差异、空库建库基线。
2. 检查备份可恢复、存储空间、依赖连通、角色授权、密钥和迁移执行身份。
3. 暂停受影响调度/接入或采用兼容写入策略，首次部署通过 db-init 执行演练过的空库建库基线。
4. 发布应用及 worker，核验健康检查、后台任务注册、连接器与权限。
5. 冒烟：登录、角色范围、三类查询、证据下钻、周期任务幂等、配置保存、导出验权。
6. 检查结果水位、隔离量、任务积压和错误，恢复接入，记录版本与部署结果。

本次为新产品首次空库建库，不设计旧库升级或历史数据搬迁；应用回滚不删除已采集数据。

## 生产上线条件

R04 汇集 V02/V03/V04 证据，确认：

- 首发三类指标清单、来源语义、授权主体与覆盖范围，未支持项不展示为零。
- 业务报告与来源基准核对，配置权限及修订机制通过。
- 性能指标依据硬件/实际负载记录；备份恢复、故障停采、断点续传及回滚演练通过。
- 监控告警、故障联系人、值守安排、运行手册、已知问题与应对措施明确。
- 无未解决的越权、证据丢失、重复计量或结果不可追溯问题；其他缺陷逐项记录接受决定。
- 生产发布按实际 GitHub Environment 等治理审批执行；代理不得代替受要求的人工审批。

当前仅形成计划，不发起生产审批、不创建标签或外部部署。

## 观察与回滚

上线后覆盖至少一个完整日报和周报周期，月报用历史完整月份回放验证，后续再核对首份自然月报告。
观察错误率、来源延迟、质量缺口、聚合水位、任务积压和报表差异，按首发基准评估，不能只看页面在线。

越权、重复计量、证据断链或不可解释的大范围差异，应暂停受影响入口/任务，保全证据，
定位影响窗口，按预案回滚兼容应用或修复数据版本。故障期间不得用零值掩盖缺数。
阈值及停止扩围条件在试点前根据实测基准确认，并记录在发布卡。

R06 每批记录新增来源/区域/站址/用户、上一批观察结果、负载余量、风险和撤回方法。
全省目标按批次达到，不把单批上线成功当成全省容量验收。
